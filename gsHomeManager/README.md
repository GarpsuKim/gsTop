# gsHomeManager

Windows 11용 텍스트/아날로그 시계 + 집 감시(WiFiScan) + 텔레그램 원격 제어(화면/웹캠 캡처, 침입 탐지) 앱입니다. 기존 gsClock, WiFiScan, screen_telegram 을 하나로 합쳤습니다. C++(g++/MinGW) 단일 소스 파일(`gsHomeManager.cpp`)이며, 버전 정보(exe 속성)는 `version.h` + `gsHomeManager.rc` 로 넣습니다. 아이콘은 `gsHomeManager.ico` 를 같은 rc 로 exe 에 넣습니다 (빌드할 때 `gsHomeManager.ico` 가 같은 폴더에 있어야 함).

## 특징

- 시계 모양 3가지: **[타이틀 & 디지탈] → [디지탈] → [아나로그]** (마우스로 더블클릭할 때마다 순환, 마지막 모양은 ini 에 저장되어 다음 실행 때 바로 그 모양으로 시작)
- 디지탈: 시분초 / 년월일 텍스트 시계, 글자가 창 안에서 좌우로 부드럽게 스크롤
- 아나로그: 원형 시계 (분 눈금 60개 + 시 눈금 12개, 시침/분침/초침, 요일(AM/PM)과 날짜 표시). 원 바깥은 완전 투명. 테마 11종, 네온사인 효과, 초침 생략, 전체화면, 모니터 바탕색 일치, 마우스 휠 확대/축소 (아래 아나로그 시계 참고)
- 일정 간격으로 창 위치를 랜덤 이동 (메뉴에서 간격 선택, 0 = 고정. 디지탈/아나로그 모두 적용)
- 세계 도시 시계 (Global): 도시를 선택할 때마다 시계 창이 추가되며, 목록은 종료 시 저장되어 재시작 시 복원 (시계 모양은 본 창과 같이 바뀜)
- 시보: 매시 지정한 분(기본 정각)에 wav 파일 재생 (메뉴 F6 > 시보 설정)
- 알람 10개 + 시스템 재시작 + 다른 앱 호출: 시각 지정, 동영상/음악 파일을 시스템 기본 플레이어로 실행, 플레이어 자동 닫기, 메모 표시, 알람 테스트
- 바탕색, 투명도, 시분초/년월일 폰트(이름, 크기, 색) 변경
- 항상 위, 모든 모니터, 모든 가상 데스크탑 적용(On/Off)
- 시분초 / 년월일 표시 형식 선택 (각 10종), 년월일 보이기 / 음력 보이기
- 음력 날짜 표시 (년월일 다음 줄, 천문연구원 공공API)
- 시계 보이기 해제 시 시스템 트레이로 이동, `tray_start=TRUE` 이면 시작할 때부터 트레이로
- 부팅(또는 로그온) 자동 실행 on/off (레지스트리 Run 키), 시작할 때 동반 실행 앱 최대 5개, `booting_alert` BAT 자동 실행
- 이미 실행 중이면 기존 앱을 정상 종료(위치/도시 목록 저장)시키고 새로 시작, 응답이 없으면 강제 종료
- 마지막 창 위치 저장
- WiFiScan: 앱 시작 시 자동으로 scan On. Bluetooth / Wi-Fi(LAN) scan 으로 집에 있는지 감시하고 `/HomeBack`, `/NotHome` 을 같은 프로세스의 Telegram 모듈에 직접 전달 (아래 WiFiScan 참고)
- `/HomeBack`, `/NotHome` 판정이 날 때마다 모니터 중앙에 5초 동안 팝업 메시지를 표시
- WiFiScan 메뉴의 HomeBack / NotHome 탐지 시간 및 프로그램 설정: 하나의 대화상자에서 탐지 사용, 항상 / 지정한 시간 동안에만 scan, `/HomeBack` · `/NotHome` 판정 때 실행할 프로그램을 설정
- 메인 윈도우 맨 아래 상태줄에 scan On / Off 가 될 때마다 시각과 사유를 표시 (아나로그 모드에서는 상태줄 없음)
- 카메라 영상: 한 창에서 WebCam1 / WebCam2(PC 웹캠) / IP Cam(안드로이드 폰 카메라 앱 DroidCam, IP Webcam 등의 MJPEG 영상)을 골라 실시간 표시, 사진 저장/동영상 촬영, 폰 탐색기(FTP)로 폰 파일 열기
- **다른 PC 원격 제어**: 같은 내부망의 다른 PC 화면을 보면서 마우스로 조작(클라이언트), 또는 이 PC 를 다른 PC 가 조작하게 허용(서버). 연결 요청이 오면 Yes/No 확인창을 띄움 (아래 다른 PC 원격 제어 참고)
- **Telegram**: 모니터/웹캠 화면을 주기적으로 텔레그램으로 전송, 봇 명령으로 PC 제어(`/shot`, `/CMD`, `/download` 등), 카메라 침입 탐지, 폰 → PC 파일 수신 (아래 Telegram 참고). 전용 스레드로 동작하므로 시계/WiFiScan 과 독립적이며, 토큰이 없으면 이 기능만 꺼집니다.
- 내부 문자열은 모두 UTF-8 (소스에 `wchar_t` 없음), 메모리 사용 최소화

## 파일 구성

```
gsHomeManager.cpp ............ 소스 (시계 + WiFiScan + IP cam + Telegram 모듈)
gsHomeManager.rc ............. exe 속성(자세히 탭) 버전 리소스 (UTF-8)
gsHomeManager.ico ............ 아이콘
wav\WAVPlayer.exe ............ 시보 재생 프로그램 (시작할 때 없으면 GitHub 에서 자동으로 내려받음)
version.h .................... 버전/저작권 정보 (버전을 올릴 때 이 파일만 수정)
version.txt .................. _build.bat 이 version.h 에서 자동 생성 (exe 와 함께 GitHub 에 올림)
_build.bat ................... 컴파일 & 링크
_build_gsHomeManagerLauncher.bat  런처 빌드
_run.bat ..................... 런처(없으면 exe) 실행
_Setup.bat ................... 시작 메뉴에 바로가기 등록
gsHomeManager.ini ............ 설정 (없으면 자동 생성. [Telegram] 섹션 포함)
README.md .................... 이 안내문
```

실행 중에 exe 폴더에 생기는 파일: `WiFiScan_result.txt`, `home.state`, `oui.txt`, `detect.state`, `pinned.id`, `image\`, `up_down\`, `IPCam\`, 그리고 모든 로그 파일은 `log\` 폴더 아래에 생깁니다: `log\gsHomeManager.log`(시계/WiFiScan/IP cam), `log\Telegram.Log`(Telegram 모듈), `log\WiFiScan_watch.log`, `log\ipcam.log`

## 빌드

MinGW-w64 의 g++ 와 windres 가 필요합니다. `gsHomeManager.cpp` 는 `version.h` 의 버전 문자열을 사용하므로 같은 폴더에 `version.h` 가 있어야 합니다. `_build.bat` 이 아래를 순서대로 수행합니다.

```bat
windres -c 65001 -I. -O coff -i gsHomeManager.rc -o gsHomeManager_res.o
g++ -Os -s -static -mwindows -Wl,--gc-sections -o gsHomeManager.exe gsHomeManager.cpp gsHomeManager_res.o -lcomdlg32 -lole32 -loleaut32 -lcomctl32 -liphlpapi -lws2_32 -lbthprops -lgdiplus -lgdi32 -lwinhttp -lmfuuid
```

- 텔레그램 통합으로 `-lwinhttp`(텔레그램 통신), `-lmfuuid`(카메라 GUID 상수만 담긴 정적 라이브러리), `-loleaut32` 가 추가되었습니다. `wininet.dll`, `mfplat.dll`, `mfreadwrite.dll` 은 실행 중에 불러오므로 링크하지 않습니다 (해당 DLL 이 없는 Windows N/KN 에서도 앱은 시작되고 카메라만 비활성).
- 실행 중인 `gsHomeManager.exe` 가 있으면 먼저 종료합니다 (파일 잠금으로 링크가 실패하는 것을 방지). 옛 `screen_telegram.exe` 도 함께 종료합니다.
- 실패하면 소스와 `build_ERR.txt` 를 메모장으로 엽니다. 성공하면 경고(있으면)와 버전/크기를 표시하고 `version.txt` 를 새로 만듭니다.
- 프로그램 이름(`APP_NAME`)과 버전은 `version.h` 의 `APP_NAME`, `APP_VERSION_NUM`, `APP_VERSION_STR` 만 고치면 됩니다. About 창, exe 속성, `version.txt`, 텔레그램 인사말, `/status`, `/version` 에 모두 반영됩니다.
- 앱은 실행할 때마다 exe 와 같은 폴더에 `version.txt` (내용: `APP_VERSION_STR`)를 새로 만듭니다.
- 새 버전 배포: `version.h` 의 버전을 올리고 빌드한 exe 와 `version.txt` 를 GitHub 저장소의 `gsHomeManager` 폴더에 올립니다. 런처(`gsHomeManagerLauncher.exe`)가 실행할 때마다 서버 버전을 확인해 갱신합니다. 예전 `screen_telegram_RUN.BAT` 의 자동 업데이트/INI 자동 다운로드는 없어졌습니다.
- `_Setup.bat` 은 런처(없으면 exe)를 시작 메뉴에 등록합니다.

## 사용법

### 마우스와 키보드

| 조작 | 동작 |
|---|---|
| 더블클릭 | 시계 모양 순환: [타이틀 & 디지탈] → [디지탈] → [아나로그] → [타이틀 & 디지탈] (모든 시계 창에 적용, ini 에 저장) |
| 한 번 클릭 | 팝업 메뉴 표시 (더블클릭이 아님이 확인된 뒤 뜨므로 약간 늦게 나타남. 메뉴 밖을 한 번 더 클릭하면 닫힘) |
| 마우스를 1초 이상 멈춤 | 도움말 풍선 `마우스를 클릭 또는 더블 클릭하세요` 가 5초 동안 표시됨 (디지탈 / 아나로그 / 도시 창 모두) |
| 클릭한 채 끌기 | 창 이동 (타이틀바 유무와 무관. 전체화면에서는 이동 안 됨) |
| 마우스 휠 (아나로그) | 시계 크기 확대/축소 (전체화면 제외) |
| F1 | 팝업 메뉴 전체 표시 |
| F2 ~ F9 | 최상위 메뉴를 순서대로 바로 열기 (메뉴 이름 앞의 `F2)` ~ `F9)` 표시) |
| ALT+F4, 창 X 버튼 | '프로그램 종료' 와 같은 확인창 |

고정 메뉴바는 없습니다. 창 높이가 메뉴바 때문에 변하지 않으며, [디지탈] / [아나로그] 모양에서는 타이틀바도 없습니다.

### 메뉴

| 키 | 메뉴 | 설명 |
|---|---|---|
| F2 | 앱 동작 설정 | 설정 초기화, 내 폰 등록(WiFiScan 대화상자), 위치 이동 간격 변경, 항상 다른 앱보다 앞에 보이기, 모든 모니터에 적용, 모든 가상 데스크톱에 적용, 시계 보이기(해제하면 트레이에서만 동작), 부팅(또는 로그온) 자동실행 on/off, 동반 실행 앱 등록, 프로그램 종료 |
| F3 | 디지탈 시계 | 바탕색 변경(시계 바탕색과 모니터 바탕색을 동일하게 / 바탕색 선택), 투명도 변경, 시분초 표시 형식, 년월일 표시 형식, 시분초 글꼴, 년월일 글꼴, 년월일 보이기, 음력 보이기 |
| F4 | 아나로그 시계 | 전체화면 on/off, 네온사인 on/off, 초침 생략 on/off, 배경색 설정, 배경 투명도, 바늘 / 눈금 / 테두리 색깔, 애니메이션 off / 애니메이션1 ~ 9, 테마 11종 |
| F5 | Global | 도시 선택(중복 선택 불가). 도시 창을 닫으면 그 도시 시계만 종료 |
| F6 | 작동시간 및 알람 설정 | 알람1 ~ 알람10, 시스템 재시작, 다른 앱 호출, 침입 탐지 시간, 시보 설정 (아래 참고) |
| F7 | WiFiScan | WifiScan모니터링(설정/진행 상황 대화상자), HomeBack / NotHome 탐지 시간 및 프로그램 설정 (아래 참고) |
| F8 | IP cam / 폰 연결 | IP cam 등록(IP address / port 를 ini 에 저장), 카메라 영상(영상 창 열기 → WebCam1 / WebCam2 / IP Cam 선택 후 [실행]), 폰 탐색기, 텔레그램/클라이언트 송수신 뷰어(텔레그램으로 받은 파일을 이미지 창으로 탐색), 다른 PC(서버), 다른 PC(클라이언트) |
| F9 | Help | About(프로그램 이름/버전/개발자), ReadMe.MD(기본 브라우저로 열기), 홈페이지(주소 표시), 최신 버전 다운로드(GitHub zip 다운로드 링크 열기), 음력 API 키값 등록, 로그 보기(로그 파일 4종을 Notepad 로 열기) |

- F3) 디지탈 시계 / F4) 아나로그 시계 메뉴는 항상 활성이며, 현재 시계 모양에 해당하는 쪽 이름 앞에 체크(✓)가 표시됩니다 ([타이틀 & 디지탈] / [디지탈] 모양이면 F3, [아나로그] 모양이면 F4). 전체 메뉴(F1 / 한 번 클릭)에서 이 둘 중 하나를 **마우스로 한 번 클릭**하면 메뉴가 닫히고 그 시계로 바뀝니다 (F3 는 마지막에 쓰던 디지탈 모양으로, 이미 그 시계이면 그대로). 마우스를 올리면 하위 메뉴가 열리는 것과 단축키 F3 / F4 로 하위 메뉴를 여는 것은 그대로입니다.
- 종료는 확인창(30초, Yes/No) 후 앱을 종료합니다. 무응답이면 계속 동작합니다. 텔레그램의 `/stop`, `/restart` 는 텔레그램에서 Yes 를 누른 뒤이므로 이 확인창 없이 바로 종료/재시작합니다.

### 앱 동작 설정

- **시계 보이기**: 해제하면 창을 숨기고 시스템 트레이 아이콘만 남습니다. 트레이 아이콘을 누르면 다시 보이고, 우클릭하면 `시계 보이기` / `프로그램 종료` 메뉴가 나옵니다. 이 값은 ini 의 `tray_start` 에도 반영됩니다 (숨긴 채 종료하면 다음에도 트레이로 시작).
- **부팅(또는 로그온) 자동실행 on/off**: 기본은 off. 켜면 "부팅 (또는 로그온)하면서 자동 실행 합니까? (Yes/No)", 끄면 해제 확인창을 거친 뒤 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 에 등록/삭제합니다.
- **동반 실행 앱 등록**: BAT / CMD / EXE / LNK 를 최대 5개까지 등록하면 앱을 시작할 때 `start ""` 로 순서대로 함께 실행합니다 (`companion_app1` ~ `5`). 이미 등록된 값은 전체 경로로 미리 보여주며, `찾기` 버튼은 시작 메뉴 폴더(모든 사용자 / 내 계정)를 기본으로 엽니다. `관리자 권한 요청 무시 (RunAsInvoker)` 를 체크하면 권한 확인창 없이 일반 권한으로 실행합니다 (`companion_run_as_invoker`). **`screen_telegram.exe` 는 등록하지 마세요** (통합되었으므로 함께 실행하면 텔레그램 getUpdates 409 충돌).
- **booting_alert**: ini 의 `booting_alert=TRUE` 이면 앱을 시작할 때마다 앱 폴더의 `booting_alert\booting_Alert_RUN.BAT` 를 창 없이 실행합니다.
- **위치 이동 간격 변경**: 0(이동 안 함) / 3초 / 5초 / 10초 / 15초 / 20초 / 30초 / 1분 / 3분 / 5분 / 10분 / 15분 / 30분. 아나로그 모양에서도 동작하며, 아나로그 전체화면 중에는 이동하지 않습니다. 이동은 창이 현재 있는 모니터의 작업영역 안에서만 일어납니다(모니터 경계를 넘지 않고, 마우스로 다른 모니터에 옮겨 놓으면 그 모니터에 머묾). 마우스 버튼을 누르고 끌고 있는 동안에는 이동하지 않습니다.
- **tray_start**: `tray_start=TRUE` 이면 시작할 때 화면에 보이지 않고 바로 트레이로 가며, "gsHomeManager 를 트레이로 보냅니다" 팝업을 5초 동안 표시합니다. 그 외에는 항상 화면에 보이는 상태로 시작합니다.

### 아나로그 시계

시계 창을 더블클릭해서 [아나로그] 모양으로 바꾸면 정사각형 창에 원형 시계가 나옵니다. 원 바깥은 완전히 투명하며(투명한 모서리는 클릭이 뒤쪽 창으로 전달됨), 투명도 설정과 함께 적용됩니다. 상단에는 `금요일 (PM)` 처럼 요일(도시 창은 도시 이름)과 AM/PM, 하단에는 날짜(yyyy-MM-dd)가 표시됩니다.

F4) 아나로그 시계 메뉴 (모두 ini `[Analog]` 에 저장):

- **전체화면 on/off** (`Full`): 시계가 있는 모니터의 가로 중앙에 고정하고 한 변을 모니터 수직 높이로 확대합니다. 전체화면에서는 요일/날짜 표시와 원 테두리가 없고, 시·분 눈금이 더 굵고 선명하며, 끌어서 이동하거나 위치 이동 타이머로 움직이지 않습니다. 더블클릭해서 다른 모양으로 바꾸면 자동으로 해제되고 켜기 전 위치와 크기로 돌아갑니다. 앱을 시작할 때 아나로그 모양이고 `Full=1` 이면 전체화면으로 바로 시작합니다.
- **네온사인 on/off** (`Neon`): 어두운 문자판 위에 테마 색으로 빛나는(번짐 3겹) 테두리/눈금/바늘. 색이 없는 테마(블랙/화이트)는 시안 색이고, 무지개 테마는 무지개 색으로 빛납니다.
- **초침 생략 on/off** (`HideSecond`): 초침을 그리지 않고, 화면을 분이 바뀔 때만(분 단위) 다시 그립니다. 알람/트레이 갱신은 계속 1초마다 확인하므로 초 단위 알람 시각은 놓치지 않습니다. 아나로그에서는 글자 스크롤 타이머가 화면을 다시 그리지 않습니다.
- **배경색 설정** (`BgMode`, `BgColor`): 시계 원 안쪽 바탕색을 고르는 서브메뉴(라디오)입니다. `모니터 배경 일치`(모니터 바탕이 단색일 때만 선택 가능, 그림이면 비활성), `테마 적용`(기본), 흰색, 회색, 검정색, 빨강, 주황, 노랑, 초록, 파랑, 남색, 보라, 핑크, `기타 (색 선택)...`(시스템 색 선택 대화상자, 고른 색은 `BgColor` 에 저장)가 있습니다. 바탕이 어두우면 눈금/글자/바늘을 밝게, 밝으면 어둡게 바꾸고, 초침이 바탕과 비슷한 색이면 흰색/검정으로 바꿉니다. 네온사인에서는 어두운 색(밝기 110 미만)일 때만 적용됩니다. 예전 ini 의 `MatchBg=1` 은 `모니터 배경 일치` 로 이어받습니다.
- **배경 투명도** (`BgAlpha`): 시계 원 안쪽 바탕의 불투명도를 10% ~ 100% 사이에서 좌우 슬라이더로 지정합니다(100% = 불투명, 기본). 슬라이더를 움직이는 동안 바로 미리보기되고 `저장` 을 눌러야 반영됩니다(`닫기` 는 원래 값으로 되돌림). 눈금/바늘/글자/테두리는 그대로 선명하게 보이고 바탕만 비칩니다. 100% 미만이면 픽셀별 알파로 그리므로 날짜 글자는 안티앨리어싱 없이 그려지고, 투명한 바탕 부분도 마우스 클릭이 됩니다(원 바깥은 그대로 통과). 시계 전체 투명도(F3 디지탈 시계 > 투명도)와 함께 적용됩니다. 네온사인에서는 번짐이 바탕과 가까울수록 함께 투명해집니다.
- **바늘 / 눈금 / 테두리 색깔** (`HourColor` / `MinColor` / `SecColor` / `BorderColor` / `TickColor`): 서브메뉴에서 `시침`, `분침`, `초침`, `테두리`, `눈금` 을 고르고, 각각 `테마 적용`(기본) 또는 `기타 (색 선택)...`(시스템 색 선택 대화상자) 중 하나를 라디오로 선택합니다. ini 값은 `Theme` 이면 테마 색, `RRGGBB` 이면 직접 지정한 색입니다. `눈금` 은 분 눈금과 시 눈금에 같은 색이 적용되고(무지개 테마도 단색으로 바뀜), 초침 색은 가운데 점에도 쓰입니다. 네온사인에서는 직접 지정한 색을 그대로 빛나게 그립니다. 애니메이션을 켜면 지정한 색을 기준으로 효과가 적용됩니다. `테두리` 는 원 테두리(베젤) 색이며 무지개 테마도 단색으로 바뀌고, 네온사인의 테두리 링과 전체화면(테두리 없음)에서는 해당 없는 부분은 무시됩니다.
- **애니메이션 off / 애니메이션1 ~ 9** (`Animate`=0~9, 0=끔): 라디오 선택입니다. 테두리, 시·분 눈금, 시·분·초침이 같은 종류로 동시에 움직입니다. 4초에 한 바퀴, 초당 약 20 프레임으로 다시 그리며, 켜면 초침 생략 상태에서도 계속 갱신합니다. 대화상자가 열려 있거나 최소화/트레이 숨김일 때는 그리지 않습니다. 전체화면에서는 테두리가 없어 눈금과 바늘에만 적용됩니다. 네온사인과도 함께 쓸 수 있습니다.
  - 애니메이션1: 테두리 빛 꼬리가 돌고 눈금을 따라 돎, 시/분침이 숨 쉬듯 밝기 변화, 초침은 부드럽게 흐름
  - 애니메이션2: 반대편 두 개의 빛이 돌고, 초침이 똑딱(지나쳤다 돌아오는 튕김)
  - 애니메이션3: 테두리/눈금/바늘이 함께 숨 쉬듯 밝아졌다 어두워짐
  - 애니메이션4: 무지개 색이 테두리/눈금/바늘에서 돌며 변함
  - 애니메이션5: 점선 테두리가 돌고 눈금이 무작위로 반짝이며 초침에 잔상
  - 애니메이션6: 레이더. 초침 뒤로 꼬리가 끌리며 지나간 테두리와 눈금이 빛남
  - 애니메이션7: 초 진행. 지난 초까지 테두리 링과 눈금이 채워지고 초침은 똑딱
  - 애니메이션8: 빛 3개가 빠르게 돌고 바늘이 빠르게 깜박임
  - 애니메이션9: 박동. 매초 시작에 전체가 번쩍였다 사라지고 초침이 튕김
- **테마** (`Theme` 0~10): 블랙, 화이트(기본), 푸른색, 빨간색, 무지개, 초록색, 금색, 보라색, 분홍색, 청록색, 세피아. 무지개 테마는 테두리와 눈금이 무지개 색입니다. 테마를 고르면 `배경색 설정` 과 시침/분침/초침/테두리/눈금 색이 모두 `테마 적용` 으로 되돌아가고(`BgMode=1`, 색 키는 `Theme`) `배경 투명도` 는 100%(`BgAlpha=100`)로 돌아가며, 그 테마가 바로 적용됩니다.
- **크기** (`Size`): 마우스 휠 한 칸마다 한 변이 약 8% 커지거나 작아집니다 (80px ~ 모니터 높이, 기본 200). 창의 중심은 그대로이며, 모든 아나로그 창(Global 도시 포함)이 같은 크기를 쓰고 마지막 크기가 ini 에 저장됩니다. 눈금/테두리/초침 굵기, 글자 크기, 네온 번짐이 크기에 비례합니다.

### 알람

알람1 ~ 알람10 은 서브메뉴 없이 일반 메뉴 항목입니다(이름 + 시각 + 파일명, 사용 중이면 앞에 체크). 어느 항목을 눌러도 하나의 **알람 설정 대화상자**가 열리며, 탭 1 ~ 탭 10 이 알람1 ~ 알람10 입니다 (누른 알람의 탭이 먼저 열림). 탭의 항목:

- **사용**: 매일 반복 (파일도 메모도 없으면 저장할 때 안내)
- **시각**: 시:분:초 (초 단위까지 지정, 5초 이내 지연은 놓치지 않음)
- **파일 선택 / 파일 지우기**: 알람 시각에 시스템 기본 플레이어로 실행할 동영상/음악
- **메모**: 알람 시각에 모니터 중앙에 30초 동안 표시 (최대 100자, 파일 없이 메모만 써도 됨)
- **플레이어 자동 닫기**: 끔 / 재생이 끝나면 / 지정 시간 후, 그리고 **닫기 시간** (0 = 닫지 않음)
- **이 알람 지우기**, **알람 테스트**(현재 입력값으로 1회 실행, 설정 변경 없음)

`저장` 을 누르면 열 개 탭의 변경 내용이 한꺼번에 ini 에 저장되고, `닫기` 는 저장하지 않습니다.

알람 메뉴 맨 아래의 두 항목:

- **시스템 재시작**: 메뉴 이름에 현재 시각이 표시되며(사용 중이면 앞에 체크), 누르면 시각과 `사용` 체크박스를 한 대화상자에서 설정합니다. 시각이 되면 확인창(300초)을 띄우고, Yes 또는 무응답이면 재시작(`shutdown /r /f /t 0`), No 이면 재시작하지 않습니다.
- **다른 앱 호출**: 서브메뉴 없이 누르면 하나의 대화상자가 열립니다(사용 / 시각 / BAT·CMD·EXE 파일 / 메모 / 알람 지우기 / 알람 테스트, `저장` 으로 반영). 시각이 되면 선택한 파일을 실행하고, 메모가 있으면 모니터 중앙에 30초 표시합니다.
- **침입 탐지 시간**: 하나의 대화상자에서 `침입 탐지 사용`, `항상`, `매일 개시 시각`, `매일 종료 시각` 을 설정합니다(사용 중이면 메뉴 앞에 체크). `항상` 이 켜져 있으면 프로그램을 시작할 때(그리고 저장할 때) 텔레그램 `/detectOn` 을 실행하고, 꺼져 있으면 매일 개시 시각에 `/detectOn`, 종료 시각에 `/detectOff` 를 실행합니다(종료가 개시보다 이르면 자정을 넘김). 시간대 안에서 프로그램을 시작하거나 설정을 저장해도 바로 `/detectOn` 을 실행합니다. 명령은 같은 프로세스의 텔레그램 모듈에 직접 전달되므로 `[Telegram]` 의 토큰/chat id 와 카메라(CAMERA=TRUE)가 필요합니다. ini 키는 `[Alarm]` 의 `DetectUse`/`DetectAlways`/`DetectStart`/`DetectEnd` (기본: 사용 안 함, 항상, 22:00:00, 06:00:00) 입니다.

- **시보 설정**: 하나의 대화상자에서 `사용`(체크), `음악파일 선택...`, `매시 NN분` (목록 00 ~ 59, 기본 00), `테스트`, `저장` 을 설정합니다(사용 중이면 메뉴 앞에 체크, 메뉴 이름 뒤에 선택한 파일명 표시). 음악 파일 선택은 `C:\Windows\Media` 를 기본 폴더로 하는 `*.wav` 탐색입니다. 이미 고른 파일이 있으면 그 폴더에서 시작합니다. `테스트` 는 저장하지 않은 현재 입력값으로 바로 재생하고, `저장` 은 ini 에 기록합니다(`사용` 을 켜려면 파일이 필요). 시계 모양(디지탈/아나로그)이나 트레이 상태와 관계없이 매시 지정한 분(0~5초)에 한 번, exe 폴더 기준 `start "" .\wav\wavplayer.exe "선택한_파일"` 를 cmd 창 없이 실행합니다. `wav\wavplayer.exe` 가 없으면 실행하지 않고 `gsHomeManager.log` 에 기록합니다 (테스트 때는 안내창). ini 키는 `[Alarm]` 의 `ChimeOn` / `ChimeFile` / `ChimeMinute` 이며, `ChimeFile` 키가 없으면 `C:\Windows\Media\ring10.wav` 를 기본값으로 씁니다.
  - **시보 제외 시간**: 대화상자 맨 아래의 `시보 제외 시간 : [시]:[분] ~ [시]:[분]` 으로 시보가 불필요한 시간(예: 사용자 취침 시간)을 지정합니다. 시작은 포함, 끝은 미포함이며 시작이 끝보다 늦으면 자정을 넘깁니다(예: 23:00 ~ 07:00). 시작과 끝이 같으면(기본 00:00 ~ 00:00) 제외 없이 매시 울립니다. 시보가 울릴 시각이 이 시간대 안이면 울리지 않고 `gsHomeManager.log` 에 `제외 시간 ... 안이라 울리지 않음` 을 남깁니다(`테스트` 버튼은 제외 시간과 관계없이 재생). ini 키는 `[Alarm]` 의 `ChimeSkipStart` / `ChimeSkipEnd` (`HH:MM`) 입니다.

자동 닫기는 파일 재생 길이(+3초)를 셸 속성으로 읽어 계산하며, 읽지 못하면 지정 시간을 사용합니다. 실행 후 8초 안에 새로 생긴 플레이어 창을 찾아 `WM_CLOSE` 를 보내는 방식이므로 다음 제약이 있습니다.

- 이미 열려 있던 플레이어 창을 재사용하거나 UWP 앱이 창을 다르게 만들면 닫히지 않을 수 있습니다.
- 재생 중 일시정지/이동하면 길이 기준 시점이 어긋납니다.

### HomeBack / NotHome 탐지 시간 및 프로그램 설정

WiFiScan 메뉴의 한 항목으로 열리는 하나의 대화상자입니다 (예전의 'Wifi공유기 자동감시 On / Off', 'HomeBack 프로그램', 'NotHome 프로그램' 메뉴를 합친 것).

- **HomeBack / NotHome 탐지 사용**: 끄면 시작할 때 scan 을 켜지 않고 개시/종료 시각도 무시합니다 (`ScanUse`, 기본 사용). 저장하면 바로 현재 상태에 맞게 scan 을 켜거나 끕니다.
- **항상**: 켜면 프로그램을 시작할 때부터 계속 scan 합니다 (`ScanAlways`). 끄면 **개시 시각** 에 scan 을 켜고 **종료 시각** 에 끄며, 시작했을 때 이미 그 시간대 안이면 바로 켭니다. 종료가 개시보다 이르면 자정을 넘깁니다. 시각은 `[WiFiScan]` 의 `ScanOnTime` / `ScanOffTime` 에 저장되며 매일 반복됩니다.
- **실행될 프로그램 지정**: HomeBack / NotHome 줄마다 `사용`(체크), 파일(`...` 로 BAT / CMD / EXE 선택), `테스트`(현재 입력값으로 1회 실행, 저장하지 않음), `삭제`(사용·파일·메모를 비움) 가 있고, `저장` 을 눌러야 반영됩니다. `/HomeBack` 또는 `/NotHome` 판정이 날 때마다 해당 프로그램을 실행합니다. 앱이 시작될 때의 첫 판정은 마지막으로 저장된 상태(`home.state`)와 다를 때만 전달·실행합니다 (아래 WiFiScan > 판정 조건 참고). 메모(`...ProgMemo`)가 ini 에 있으면 모니터 중앙에 30초 표시합니다 (이 대화상자에서는 바꾸지 않고 그대로 보존).
- **NotHome 판정 기준**: 대화상자 맨 아래의 목록(1, 2, 3, 5, 10, 15, 30분)에서 선택합니다. 이 시간 동안 사용자 폰이 응답하지 않으면 NotHome 으로 판정합니다. `저장` 시 ini `[WiFiScan]` 의 `NotHome`(초)에 기록되고 실행 중인 감시에 바로 반영됩니다. 시간이 짧은 경우(예: 1분)에는 연속 실패 횟수(`NotHomeFails`)가 그 시간 안에 들어가는 확인 주기 수를 넘지 않도록 자동 조정됩니다. ini 에 목록에 없는 초 값이 있으면 가장 가까운 칸이 표시되며, 이 항목을 바꾸지 않고 저장하면 원래 값이 보존됩니다.
- 예전에 ini 의 `ScanOn*` / `ScanOff*` 에 설정해 둔 음악/동영상·메모·플레이어 자동 닫기 값은 지우지 않으며, 개시/종료 시각이 되면 예전처럼 실행됩니다 (이 대화상자에서는 바꿀 수 없고 ini 를 직접 고칩니다).
- ini 에 `ScanOnTime` 이 이미 있던 사용자는 `ScanAlways` 가 꺼진 상태(예전 예약 유지)로, 없던 사용자는 켜진 상태(예전처럼 시작할 때 항상 scan)로 시작합니다.
- ini 키: `[WiFiScan]` 의 `ScanUse`, `ScanAlways`, `ScanOnTime`, `ScanOffTime`, `HomeBackProgOn/File/Memo`, `NotHomeProgOn/File/Memo`.


### 상태줄과 명령 전달 팝업

- 메인 윈도우 맨 아래 줄에 `HH:MM:SS  scan On - 사유` / `scan Off - 사유` 형식으로 마지막 상태를 표시합니다 (프로그램 시작, 대화상자, 예약 시각). [아나로그] 모양에서는 상태줄이 없습니다.
- `/HomeBack`, `/NotHome` 을 Telegram 모듈에 전달할 때마다 모니터 중앙에 5초 동안 `텔레그램 명령 전달: ...` 팝업을 띄웁니다 (클릭하면 닫힘).

## WiFiScan

앱이 시작되면 scan 이 자동으로 On 되며, 메뉴 **WiFiScan > WifiScan모니터링** 으로 대화상자를 엽니다.

- 입력: scan 주기(초). 블루투스 MAC / LAN 카드 MAC 칸은 직접 입력할 수 없고, 목록의 체크박스로만 지정합니다
- 메뉴 **앱 동작 설정 > 내 폰 등록** 은 같은 대화상자를 '본인 스마트폰 항목에 체크하고, 저장 버튼을 누르세요' 안내와 함께 엽니다
- 설정값은 `gsHomeManager.ini` 의 `[WiFiScan]` 에 저장
- 체크박스: Wi-Fi, Bluetooth (체크하면 scan 대상)
- 버튼: **저장**(저장 후 바로 적용), **취소**(저장 안 함), **scan재시작**(저장 후 재시작), **scan Off**(작업 정지)
- 대화상자 중하단: IP 주소, 컴퓨터 이름, MAC 주소, 네트워크 어댑터 제조사, 사용자 텍스트 목록과 진행 상황 (빨강=OFF, 노랑=확인 중, 초록=ON)
- 목록 맨 앞 체크박스: 체크한 행의 MAC 이 해당 입력 칸(블루투스 행 = 블루투스 MAC, Wi-Fi 행 = LAN 카드 MAC)에 들어가며, **저장/scan재시작** 때 ini 에 기록됩니다. 입력 칸과 같은 MAC 의 행은 자동으로 체크됩니다. 블루투스 행의 IP Address 칸에는 `<blue tooth>` 로 표시되고, 모든 칸이 빈 행은 표시하지 않습니다.
- 대화상자를 닫아도 scan 은 계속 진행됩니다 (멈추려면 scan Off).
- 생성 파일은 기존 WiFiScan 과 동일: `WiFiScan_result.txt`, `WiFiScan_watch.log`, `oui.txt`(제조사 조회)
- 집에 있는지(HomeBack) / 없는지(NotHome) 판정은 `trigger.txt` 파일이 아니라 같은 프로세스의 Telegram 모듈로 직접 전달됩니다 (아래 Telegram 의 로컬 트리거). 예전의 `trigger.txt`, `wifiscanTriger.txt` 는 더 이상 쓰지 않습니다.
- 기존 WiFiScan.exe 는 중복되므로 함께 실행하지 마세요.

### 판정 조건 (집 안팎)

- **확인 방법**: 감시 주기(`WiFiScanWatchInterval`)마다 블루투스를 먼저 확인하고, 확인되지 않으면 LAN 카드(Wi-Fi) 를 확인합니다. 둘 중 하나라도 확인되면 집에 있는 것으로 봅니다.
- **`/NotHome`**: 둘 다 확인되지 않은 횟수가 연속 `NotHomeFails` 회 이상이고(기본 5), 미확인 시간도 `NotHome` 초 이상(기본 300 = 5분)일 때만 판정합니다. 두 조건을 모두 채워야 하므로 일시적인 무응답(폰 절전 등)으로는 판정되지 않습니다. 한 번이라도 확인되면 횟수는 0 으로 돌아갑니다.
- **시작 직후에도 같은 유예**: 앱/scan 을 (재)시작한 뒤 첫 확인이 실패해도 바로 `/NotHome` 으로 보지 않습니다. 같은 조건(연속 횟수 + 시간, 한 번도 확인 못 했으면 감시 시작 시각부터 계산)을 채울 때까지 `초기 상태 판정 보류` 로 기록하고, 그 전에 확인되면 `/HomeBack` 입니다.
- **재시작해도 같은 상태는 다시 알리지 않음**: 마지막 판정 상태를 exe 폴더의 `home.state`(`HOME` / `AWAY`) 에 저장합니다. 시작 직후의 첫 판정이 저장된 상태와 같으면 로그에만 남기고 텔레그램 명령과 HomeBack / NotHome 프로그램은 실행하지 않습니다. 상태가 바뀐 판정, 또는 `home.state` 가 없을 때(처음 실행)는 전달합니다. 상태를 강제로 다시 알리고 싶으면 `home.state` 를 지우고 다시 시작하세요.
- `NotHomeFails` 는 `[WiFiScan]` 에 있고 ini 를 직접 고칩니다 (0 이면 5, 이 값이 클수록 외출 판정이 늦고 오탐이 줄어듭니다). 실행 중에는 scan 재시작 때 반영됩니다. 예전 기본값(`NotHome=60`, `NotHomeFails=3`)을 그대로 쓰던 ini 는 새 기본값(300 / 5)으로 **한 번만** 올리고 `NotHomeRule=2` 를 기록합니다 (그 뒤에 직접 고친 값은 그대로 유지).
- **PC 자신의 네트워크가 없을 때**(LAN/Wi-Fi 끊김)는 폰이 없다는 증거가 아니므로 미확인 횟수에 넣지 않고 판정을 보류합니다 (`PC 의 네트워크 어댑터가 없어 판정을 보류합니다`).
- **감시 공백**: PC 절전/멈춤 등으로 감시 주기가 `max(180초, 감시 주기×6)` 보다 오래 끊겼다가 돌아오면 그 동안은 외출 증거로 보지 않고 미확인 시간과 횟수를 다시 셉니다 (`감시 공백 …`).

### scan 속도

- **감시 확인**: 블루투스 우선, 그다음 LAN 카드. LAN 카드는 고정 IP → 이전 IP → 이 PC 의 이웃(ARP) 캐시에 있는 IP 순으로 한 번씩 확인하고, 그래도 없을 때만 254개 IP 전체 ARP 검색을 합니다. 전체 검색은 60초에 한 번만 하므로 폰이 없는 동안(집을 비운 동안) 매 주기마다 네트워크를 훑지 않습니다.
- **시작할 때 전체 scan**: 같은 서브넷에서는 ARP 응답이 곧 존재 증거이므로 ARP 를 먼저 보내고 응답이 없으면 그 IP 는 바로 건너뜁니다 (예전에는 ping 과 ARP 를 모두 기다려 없는 IP 마다 대기가 두 배였음). 이전에 보였던 장치만 ping 으로 한 번 더 깨워 봅니다. 블루투스 scan 은 Wi-Fi scan 과 동시에 진행합니다.

### 판정 사유 기록 (`WiFiScan_watch.log`)

`/HomeBack`, `/NotHome` 판정이 날 때마다 `[사유]` 줄을 한 줄 남깁니다 (`텔레그램 모듈에 명령 전달` 줄 바로 앞). 판정 요약 | 블루투스 확인 결과 | LAN 카드 확인 결과 순서입니다.

```
AWAY (60초 연속 미확인)
[사유] /NotHome - 마지막 확인 17:48:06 (Bluetooth), 60초 연속 미확인 (외출 판정 60초): 블루투스와 LAN 카드 둘 다 무응답 | 블루투스: 무응답 - 응답 없음 (8초 시간 초과) | LAN 카드: 무응답 - 응답 없음 (HomeMac F0-F5-64-13-CF-32: 범위 192.168.0.1 ~ 192.168.0.254 전체 ARP 검색에서 해당 MAC 없음)
```

- **`/NotHome` 요약**: `블루투스와 LAN 카드 둘 다 무응답` / `LAN 카드 무응답 (블루투스는 확인 수단 아님)` / `블루투스 무응답 (LAN 카드는 확인 수단 아님)`. 마지막 확인 시각과 방식, 연속 미확인 시간도 함께 남깁니다.
- **`/HomeBack` 요약**: `블루투스 응답` / `블루투스 무응답이었으나 LAN 카드 응답` / `LAN 카드 응답`. 외출 상태에서 복귀한 경우 외출 경과 시간(`NotHome 판정 후 N분 M초 경과`)을 남깁니다. 앱을 시작할 때의 첫 판정은 `감시 시작 시점에 …` 로 구분됩니다.
- **블루투스 상세**: 연결 상태 / 호출 응답 없음(8초 시간 초과, 오류 번호) / PC 에 페어링되어 있지 않음 / 어댑터 없음·꺼짐 / MAC 미지정 / scan 대상 아님(체크 해제)
- **LAN 카드 상세**: 고정 IP ARP·ping 무응답 / 이전 IP 무응답 / 전체 범위 ARP 검색에서 해당 MAC 없음 / PC 의 네트워크 어댑터·IP 범위 없음(PC 의 LAN 끊김) / MAC 미지정 / scan 대상 아님(체크 해제)
- 블루투스가 응답하면 LAN 카드는 확인하지 않으므로(블루투스 우선) 이때 LAN 카드 칸은 `확인 안 함 - 블루투스 응답으로 확인 생략` 으로 표시됩니다.
- `/NotHome` 은 블루투스와 LAN 카드가 모두 무응답인 상태가 위 판정 조건(연속 `NotHomeFails` 회 + `NotHome` 초)을 채울 때만 판정되므로, 한쪽만 무응답이면 판정되지 않습니다. 감시 대상이 한쪽뿐이면 그쪽만 무응답이어도 판정됩니다. 로그에는 `연속 N회 / M초 미확인 (외출 판정: 연속 X회, Y초)` 가 함께 남습니다.

## Telegram

주기적으로 모니터(와 웹캠)의 화면을 캡처해 텔레그램으로 보내고, 텔레그램 봇 명령으로 PC 를 제어합니다. 앱이 시작되면 전용 스레드로 시작하며, 설정은 `gsHomeManager.ini` 의 **`[Telegram]`** 섹션에서 읽습니다.

### 설정 시작하기

- `[Telegram]` 섹션이 없으면 첫 실행 때 자동으로 만듭니다. 예전 `screen_telegram.ini` 가 exe 폴더나 `..\screen_telegram\` 에 있으면 그 내용을 그대로 가져오고(원본은 건드리지 않음), 없으면 빈 토큰과 기본값 견본을 씁니다.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 를 채우고 앱을 다시 시작하면 동작합니다. 둘 중 하나라도 없으면 텔레그램 기능만 사용하지 않고 나머지(시계, WiFiScan 등)는 정상 동작합니다.
- ini 는 시작할 때만 읽습니다. 텔레그램 `/INTERVAL=nnn`, `/ini` 는 이 섹션을 고칩니다 (다른 섹션과 주석, 줄바꿈은 그대로 유지).
- 보안: ini 에 봇 토큰이 평문으로 들어 있으므로 공유/업로드 금지 (노출 시 BotFather 에서 `/revoke`). GitHub 에 올리는 ini 에는 견본 값만 넣을 것.

### 동작

- 이미지는 JPEG(품질 85)로 전송. 긴 변이 2560px 를 넘는 화면(4K 등)은 전송용만 2560px 로 줄여 보내고 `image` 폴더 저장본은 원본 그대로. 텔레그램 연결(WinHTTP 세션)은 재사용하며 명령 폴링은 10초 롱폴링. 전송 실패(네트워크/5xx/429) 시 최대 3회 시도
- 이미지가 10MB 를 넘으면 품질/해상도를 단계적으로 낮춰 전송. 가로+세로 10000px 초과 또는 비율 20:1 초과이면 원본을 문서(sendDocument)로 전송
- 모니터 번호는 "주 모니터=1, 나머지는 왼쪽->오른쪽" 순이며, Windows 디스플레이 설정의 번호와 다를 수 있음
- 카메라가 여러 개면 `CAMERA_INDEX` 로 선택 (목록은 최초 캡처 시 `Telegram.Log` 에 출력)
- 잠금 화면/로그온 전에는 화면 캡처를 건너뜀 (카메라는 계속 시도). 서비스(세션 0)로는 화면 캡처 불가. 사용자 로그온 후 시작프로그램/작업 스케줄러(로그온 시)로 실행
- 고DPI 환경에서도 실제 해상도로 캡처합니다 (이 모듈의 스레드만 DPI 인식으로 설정하므로 시계 창 크기에는 영향 없음)
- 전송 전에 모든 이미지를 exe 폴더의 `image` 폴더에 저장 (파일명: `YYYYMMDD_HHMMSS_Monitor1.jpg`, `..._Camera.jpg`)
  - 기본은 자동 삭제 없음 (30초 간격, 모니터+카메라면 하루 약 3GB). `KEEP_DAYS=N`(N일 지난 이미지 삭제), `KEEP_MAX_FILES=N`(최대 N개, 오래된 것부터 삭제)로 자동 정리. 이 프로그램이 만든 파일명(`YYYYMMDD_HHMMSS_*.jpg/png`)만 삭제함
- `CAMERA_KEEP_OPEN=TRUE` 이면 카메라를 계속 열어 둠 (지연/LED 깜빡임 감소, 대신 다른 앱이 카메라를 쓸 수 없음. 기본 FALSE)
- `SAVE_ONLY=TRUE` 이면 이미지를 텔레그램으로 보내지 않고 `image` 폴더에 저장만 함. 명령 수신은 계속 동작하며 `/shot` 만 전송 (TOKEN/CHAT_ID 가 없으면 이 모듈 자체가 꺼짐)
- `MAX_LOOP=N` 이면 N회 캡처/전송 후 Telegram 모듈이 끝남 (0 또는 생략 시 무제한. 시계 등 나머지 앱은 계속 동작). 침입 탐지가 켜져 있으면 모듈이 계속 동작
- 시작 인사말: 준비가 끝나면 텔레그램으로 인사말(간격/카메라/침입 탐지 상태 포함)을 한 번 전송. `TELEGRAM_GREETING=FALSE` 로 끌 수 있음
- 상단 고정 메시지: 채팅창 상단에 현재 침입 탐지 상태 하나만 고정해 보여 줌 (켜짐 "❤️ /detectOn", 꺼짐 "💙 /detectOff", 카메라가 없거나 `CAMERA=FALSE` 이면 "❤️ 카메라가 작동하지 않습니다"). 상태가 바뀔 때마다 같은 메시지를 고쳐 쓰며, 메시지 id 는 `pinned.id` 에 저장 (지우거나 풀었으면 다음 갱신 때 다시 만듦). 시작할 때 처음 상태는 최근 로컬 트리거(`/NotHome`=켜짐, `/HomeBack`=꺼짐)가 있으면 그것을, 없으면 실제 상태를 따름

### 텔레그램 명령

`TELEGRAM_COMMANDS=TRUE`(기본) 일 때 봇에게 보낼 수 있는 명령입니다 (대소문자 구분 없음).

| 명령 | 동작 |
|---|---|
| `/shot` | 화면 + 카메라 즉시 캡처·전송 |
| `/screen` | 화면만 즉시 캡처·전송 |
| `/photo` | 카메라만 즉시 캡처·전송 |
| `/pause`, `/resume` | 이미지 전송 중단(저장은 계속) / 재개 |
| `/status` | 상태 |
| `/detectOn`, `/detectOff` | 침입 탐지 켜기 / 끄기 |
| `/INTERVAL=nnn` | 캡처·전송 간격을 nnn초로 변경 (5~86400, 즉시 적용되고 ini 의 `TELEGRAM_INTERVAL` 도 갱신). `/INTERVAL` 만 보내면 현재 값 표시 |
| `/version` | 프로그램 버전과 빌드 시각 |
| `/log [n\|all]` | 실행 로그(`Telegram.Log`) 전송. 인자 없으면 최근 50줄, `/log n` 은 최근 n줄(1~2000), `/log all` 은 전체. 4096자를 넘거나 `all` 이면 .txt 문서로 전송. `Telegram.Log.old` 는 보지 않음 |
| `/CMD 명령` | `/CMD` 뒤 문자열 전체를 PC 의 `cmd.exe /c` 에서 실행하고 결과(표준 출력+오류)를 `cmd_YYYYMMDD_HHMMSS.txt` 로 전송 |
| `/download` | PC 화면에 파일 선택 창을 띄워 고른 파일들을 전송 |
| `/down 옵션` | 폴더의 파일을 모두 전송 (하위 폴더 제외). 옵션: `사진` / `동영상` / `음악` / `문서` / `폴더_full_path` |
| `/ini 키=값` | `[Telegram]` 섹션 끝에 새 키 추가 |
| `/github` | PC 기본 브라우저로 GitHub 의 README 페이지 열기 (주소는 소스의 `kGithubUrl`) |
| `/HomeBack` | 귀가 인사 "[집에 돌아 오신 것을 환영합니다. 푹 쉬세요]" 후 자동으로 `/detectOff` + `/pause` |
| `/NotHome` | 외출 인사 "안녕히 다녀오세요. 제가 집을 잘 지키고 있겠습니다." 후 자동으로 `/detectOn` + `/resume` |
| `/restart` | Yes/No 확인 후 **프로그램 전체**를 종료하고 같은 exe 를 다시 실행 |
| `/stop` | Yes/No 확인 후 **프로그램 전체**(시계, WiFiScan 감시 포함)를 종료 |
| `/help` 또는 `//` | 도움말 |

- `/stop`, `/restart` 는 "종료하시겠습니까?(y/n)" 메시지에 Yes/No 버튼이 붙어 옴. Yes 를 눌러야 실행, No 는 취소. 버튼은 명령과 같은 chat/허용 사용자만 누를 수 있고, 5분이 지났거나 이미 처리한 메시지, 프로그램 재시작 전의 메시지 버튼은 무효. `/restart` 는 종료 처리가 끝나기를 최대 12초 기다린 뒤 새 프로세스를 띄웁니다.
- `TELEGRAM_CHAT_ID` 로 설정한 chat 의 명령만 처리. 명령은 별도 스레드가 받으므로 캡처/전송 중에도 `/pause` `/resume` `/status` `/stop` 은 수 초 내 반응 (`/shot` 은 진행 중인 캡처가 끝난 뒤 실행)
- `TELEGRAM_CHAT_ID` 가 그룹(음수)이면 `TELEGRAM_ALLOWED_USER_IDS=111,222` (명령 허용 사용자 ID)를 반드시 설정해야 명령이 동작. 개인 chat 이면 생략 가능
- 같은 봇 토큰을 다른 프로그램이 getUpdates/webhook 으로 쓰면 409 충돌이 나므로, 이 앱 전용 봇을 쓰는 것을 권장

**/ini 키=값** (예: `/ini INTRUSION_COOLDOWN=120`, `[키=값]` 처럼 대괄호로 감싸도 됨)
- 같은 키(대소문자 무시)가 `[Telegram]` 섹션에 이미 있으면 경고만 보내고 삽입하지 않음. 값을 바꾸려면 ini 를 직접 수정 (캡처 간격은 `/INTERVAL=nnn`)
- `;KEY=값` 처럼 주석 처리된 줄은 없는 키로 봄. 키 이름은 영문/숫자/_ (64자 이내, 대문자로 저장), 값은 한 줄 400자 이내
- 프로그램이 해석하지 않는 키이면 추가는 하되 오타 주의 메시지를 함께 보냄
- ini 는 시작할 때만 읽으므로 추가한 값은 앱을 다시 시작해야 적용됨. 로그에는 키 이름만 남기고 값은 남기지 않음

**/CMD 명령**
- 명령 뒤 문자열(앞뒤 공백만 제거)이 그대로 `cmd.exe /c` 에 전달됨. 명령이 비어 있으면 사용법만 알려 줌. 예: `/CMD dir /b`, `/CMD ipconfig /all`, `/CMD type log\Telegram.Log | findstr UPDATE`
- 캡션에 실행한 명령, 종료 코드, 소요 시간, 출력 크기를 표시. 출력이 없으면 "(출력 없음)" 메시지만 전송
- 실행 창은 숨김, 표준 입력은 NUL. 시작 폴더는 프로그램의 현재 폴더. 제한 시간 60초(넘으면 하위 프로세스까지 강제 종료하고 그때까지의 출력 전송), 출력 20MB 초과분은 잘림
- 실행하는 동안 명령 수신 스레드가 대기하므로 다른 텔레그램 명령(`/stop` 포함)은 끝난 뒤 처리됨 (최대 60초)
- 한글 출력: 출력이 UTF-8 이 아니면 콘솔 코드 페이지(한국어 Windows 는 CP949)에서 UTF-8 로 변환해 전송
- 보안 주의: 허용된 chat/사용자가 PC 에서 임의의 명령을 실행할 수 있는 기능. 텔레그램 계정과 그룹 chat 의 허용 사용자 목록을 안전하게 관리할 것. 실행한 명령(200자까지)과 종료 코드는 `Telegram.Log` 에 기록. 사용자 로그온 세션의 권한으로 동작 (관리자 권한이 필요한 명령은 앱을 관리자로 실행해야 함)

**/download**
- PC 앞에 있는 사람이 파일을 고르는 방식. 창은 항상 맨 위에 뜨고, 5분 안에 고르지 않거나 취소하면 "취소/시간 초과" 메시지만 보냄
- 파일 1개당 49MB 까지(원본 그대로 sendDocument). 빈 파일, 49MB 초과, 열 수 없는 파일은 건너뛰고 완료 메시지에 파일별 사유를 표시. 전송된 파일명은 `Telegram.Log` 에 기록
- 창이 떠 있는 동안 명령 수신 스레드가 대기하므로 다른 명령은 창을 닫은 뒤 처리됨 (최대 5분). 잠금 화면/로그오프 상태에서는 5분 뒤 자동 취소됨

**/down 옵션**
- 옵션은 대소문자 무시. 사진 = `사진` `이미지` `photo` `photos` `image` `images`, 동영상 = `동영상` `video` `videos`, 음악 = `음악` `music`, 문서 = `문서` `document` `documents`. 그 밖의 문자열은 폴더 전체 경로로 봄 (예: `/down D:\Backup\2026`)
- 사진/동영상/음악은 사용자 계정의 기본 사진/동영상/음악 폴더에서 해당 종류의 확장자 파일만, 문서 폴더와 폴더 경로는 모든 파일을 이름순으로 전송. 하위 폴더는 제외
- 파일 1개당 49MB 까지, 한 번에 최대 200개(`kDownMaxFiles`, 넘으면 나머지는 건너뜀). 초과/빈 파일/열 수 없는 파일은 건너뛰고 완료 메시지에 사유를 표시. 전송이 끝날 때까지 명령 수신 스레드가 대기하므로 다른 명령은 끝난 뒤 처리됨

**텔레그램 명령 메뉴**: 시작할 때 `setMyCommands` 로 봇 채팅 입력창의 "메뉴" 버튼(`/` 명령 목록)에 명령과 설명을 등록합니다. 메뉴 이름은 소문자만 허용되어 `/shot /screen /photo /pause /resume /status /detecton /detectoff /interval /ini /log /cmd /download /down /github /homeback /nothome /version /restart /stop /help` 로 등록되며 명령은 대소문자를 구분하지 않으므로 동일하게 동작합니다. 인자가 필요한 `/ini` `/cmd` 는 인자 없이 눌리면 사용법만 안내합니다. 시작할 때마다 등록하므로 BotFather 에서 직접 만든 목록은 덮어써집니다 (직접 관리하려면 `TELEGRAM_MENU=FALSE`). 새 목록이 앱에 바로 안 보이면 채팅방을 나갔다 다시 들어오거나 텔레그램 앱을 다시 시작하세요.

### 로컬 트리거 (WiFiScan 감시 → Telegram)

`LOCAL_TRIGGER=TRUE`(기본) 이면 같은 프로세스의 WiFiScan 감시(HomeWatcher)가 넘기는 `/HomeBack`, `/NotHome` 을 1초 안에 받아 해당 명령을 처리합니다. 예전에는 `trigger.txt` 파일로 다른 프로세스가 전달했지만 이제는 프로세스 안의 큐로 전달하므로 파일을 쓰지 않습니다.

- 텔레그램을 거치지 않는 이유: 봇이 sendMessage 로 보낸 "/HomeBack" 글은 봇 자신이 getUpdates 로 받지 못해 처리되지 않기 때문
- 허용 명령은 `/HomeBack`, `/NotHome` 두 개뿐이며, 300초가 지난 요청은 버립니다. 앱이 시작되기 전에 이미 넘겨진 첫 판정(부팅 직후)도 300초 안이면 처리합니다.
- 처리 결과(인사말, 침입 탐지 켜기/끄기 안내)는 평소처럼 텔레그램으로 전송. 명령 처리는 명령 수신 스레드와 순서대로 진행되므로 `/CMD`, `/download` 창 처리 중이면 끝난 뒤 실행

### 침입 탐지 (CAMERA=TRUE 필요)

ini 스위치가 없고 텔레그램 명령 `/detectOn`(켜기) `/detectOff`(끄기)로 제어합니다. 켜면 카메라를 상시 열어 `INTRUSION_CHECK_MS`(기본 1000ms)마다 프레임을 검사하고, 끄면 카메라를 해제합니다.

- `AUTO_DETECT=TRUE` 이면 시작 때 `/detectOn` 을 자동 수행 (인사말에도 "침입 탐지: 켜짐"). FALSE/없음이면 exe 폴더의 `detect.state` 파일(ON/OFF)에 저장된 마지막 상태를 따름. 파일이 없으면 꺼짐
- 움직임이 확정되면 "[침입탐지 : yyyy년 mm월 dd일 HH시 mm분 ss초]" 메시지를 보낸 뒤 카메라 이미지만 전송 (모니터 화면 캡처는 하지 않음. `SAVE_ONLY`, `/pause` 와 무관하게 무조건 전송). 파일명은 `YYYYMMDD_HHMMSS_Intrusion_Camera.jpg`
- 방식: 그레이스케일+블러 → 이동평균 배경 차분 → 픽셀 임계값(`INTRUSION_PIXEL_THRESHOLD`, 기본 25) + 변화 면적(`INTRUSION_AREA_PERCENT`, 기본 1.0%) → 연속 프레임 확인(`INTRUSION_CONFIRM_FRAMES`, 기본 2) → 쿨다운(`INTRUSION_COOLDOWN`, 기본 60초). 조명 켬/끔·자동 노출 변화(화면 60% 이상 변화)와 시작 직후 안정화 구간은 탐지하지 않음
- 완전히 별도의 스레드로 동작: 주기 캡처, `/pause`, `/shot`, 전송 재시도 등과 무관하게 계속 프레임을 검사하고, 침입 확정 시 그 스레드가 직접 메시지 + 카메라 이미지(탐지된 바로 그 프레임) 저장·전송을 수행
- 탐지 중에는 카메라를 이 스레드가 전담(주기 캡처와 `/photo` 는 이 스레드의 최신 프레임을 사용)하므로 LED 가 항상 켜져 있고 다른 앱(화상회의 등)이 카메라를 쓸 수 없음
- `MAX_LOOP` 횟수를 채운 시점에 침입 탐지가 켜져 있으면 모듈이 끝나지 않고 계속 동작
- 오탐이 많으면 `AREA_PERCENT`/`PIXEL_THRESHOLD` 를 올리고, 놓치면 낮춤

### 파일 수신 (폰 → PC)

텔레그램 봇 채팅에 파일(문서/사진/동영상/오디오/음성)을 첨부해 보내면 PC 의 `up_down` 폴더(`UPLOAD_DIR`) 안 날짜별(`YYYY-MM-DD`) 하위 폴더에 자동 저장하며, 파일 이름 앞에 `tg_` 가 붙습니다 (예: `up_down\2026-11-17\tg_사진.jpg`. 원격 제어로 주고받은 파일도 같은 `up_down\날짜` 폴더에 저장되며 `tg_` 는 붙지 않음).고 "저장 완료: 경로 (크기)" 를 알려 줍니다. 별도 명령은 없습니다.

- 명령과 같은 chat/허용 사용자가 보낸 파일만 받음. `TELEGRAM_COMMANDS=FALSE` 이면 받지 않음. 앱이 꺼져 있는 동안 보낸 파일은 시작할 때 건너뜀
- 파일 1개당 20MB 까지 (텔레그램 봇 API 한도). 넘으면 "너무 커서 받을 수 없음" 메시지. 사진은 텔레그램이 압축한 것이 오므로 원본이 필요하면 폰에서 "파일로 보내기"로 첨부
- 파일명은 정리해서 저장: 경로 제거, 금지 문자(`<>:"/\|?*`) → `_`, CON/NUL 같은 예약어 회피, 150자 제한. 같은 이름이 있으면 `이름_1.확장자`, `이름_2.확장자` ... 로 저장하고 덮어쓰지 않음. 이름이 없는 사진 등은 `YYYYMMDD_HHMMSS_file_N.jpg` 형태. 저장 폴더는 한 단계만 자동 생성하므로 `UPLOAD_DIR` 의 상위 폴더는 미리 있어야 함
- 저장만 하고 실행하지 않음 (단 .mp4/.mp3 는 아래 설명대로 재생)
- 파일을 받기 시작할 때마다(파일 1개마다) 화면 중앙에 큰 글자로 **"텔레그램으로부터 업로드 중입니다"** 팝업을 1초 동안 표시합니다 (클릭하면 바로 닫힘). 여러 개를 연속으로 받으면 팝업도 개수만큼 조금씩 어긋나게 뜹니다.
- 받은 파일이 이미지(jpg/png/bmp/gif/tif)이면 저장 직후 PC 화면에 이미지 창을 띄움 (`UPLOAD_SHOW_IMAGE=FALSE` 로 끌 수 있음). 기본 세로 높이는 모니터 세로의 90% (이미지는 창 안에 비율을 유지해 맞춤), 기본 가로폭은 모니터 가로폭의 80% 이고 (이미지가 그보다 크면 이미지 크기에 맞춰 열림, 모니터는 넘지 않음) 처음 위치는 모니터 중앙이며, 크기 조절 가능(비율 유지), Esc 또는 닫기 버튼으로 닫음. 창은 하나뿐이라 여러 장을 연속으로 받아도 새 창을 만들지 않고, 이미 떠 있는 창의 이미지만 교체합니다 (기존 이미지는 좌로 빠르게 스크롤되어 나가고 새 이미지가 들어옴). 창 상단 버튼(왼쪽부터): `목록 비우기` (맨 앞 버튼. 목록이 비어 있지 않을 때만 활성이며, 누르면 목록의 모든 항목을 목록에서만 빼고 파일은 지우지 않음. 창은 닫히지 않고 빈 뷰어로 남으며, 이후 받은/추가한 파일이 다시 채움) / `up_down 탐색기` (현재 파일이 들어 있는 폴더를 Windows 탐색기로 열고 그 파일을 선택. 텔레그램으로 받은 파일은 `UPLOAD_DIR` 폴더) / `좌 90° 회전` / `우 90° 회전` (표시만 돌리며 파일은 그대로) / `◀◀` SlideShow(좌) / `◀` 직전 이미지 / `▶` 직후 이미지 / `▶▶` SlideShow(우) (창이 열려 있는 동안 받은 순서. 키보드 ←/→ 도 동작) / `삭제` (Yes/No 확인 후 PC 에서 파일 삭제, `Delete` 키도 동일) / `목록 추가` (시스템 기본 파일 선택 대화상자에서 여러 파일을 골라 기존 목록 뒤에 추가하고 처음 추가한 파일을 보여 줌. 이미 목록에 있는 파일은 건너뛰고, 이미지가 아니거나 이미지로 읽을 수 없는 파일은 정보 화면으로 보임) / `실행` (기본은 비활성이며, 현재 표시 중인 것이 이미지가 아닌 파일일 때만 활성. 누르면 그 파일을 시스템에 넘겨 연결된 프로그램으로 열거나 실행함)) / `텔레그램으로 보내기` (맨 마지막 버튼. 목록이 비어 있지 않을 때만 활성이며, 누르면 먼저 **"이 목록의 파일들을 텔레그램으로 보내시겠습니까? (Yes/No)"** 확인창이 뜨고, `Yes` 이면 목록의 파일 전체를 텔레그램 `/down` 처리로 PC 에서 텔레그램 chat 으로 전송함. 파일은 문서로 하나씩, 1개당 49MB 까지, 한 번에 최대 200개이며 파일을 하나 보낼 때마다 화면 중앙에 큰 글자 팝업(`텔레그램으로 보내는 중입니다 (3/10)` + 파일 이름, 1초)이 뜨고 이 창이 그 파일을 자동으로 보여 주며, 진행/결과는 텔레그램 메시지로도 알려 줌. 텔레그램 토큰/chat id 가 없거나 `LOCAL_TRIGGER=FALSE` 이면 안내창만 뜸). `◀◀`(SlideShow 좌) / `▶▶`(SlideShow 우) 버튼과, 둘째 줄의 `시간 간격(초)` 목록(1, 2, 3, 5, 10, 15, 20, 30, 60, 120, 180, 300, 600초, 기본 3초)이 있습니다. 그 옆의 `전환 효과` 목록은 SlideShow 로 이미지가 바뀔 때의 효과를 고릅니다: 좌우 스크롤(기본) / 상하 스크롤 / 페이드 / 와이프 / 덮기 / 가운데서 열기 / 박스 확대 / 가로 블라인드 / 세로 블라인드 / 모자이크 / 무작위(매번 다른 효과). 좌우·상하 스크롤, 와이프, 덮기는 ◀◀/▶▶ 방향을 따릅니다. 효과는 SlideShow 실행 중에만 적용되며, ◀/▶ 로 직접 넘기거나 텔레그램으로 받은 이미지가 들어올 때는 항상 좌우 스크롤입니다. 두 버튼은 **목록에 이미지 파일이 2개 이상일 때만 활성**이며, 목록에서 이미지 파일만 골라 선택한 간격마다 자동으로 넘깁니다 (이미지가 아닌 파일은 건너뜀). `◀◀` 는 `◀` 와 같은 방향(목록 역순, 기존 이미지가 우로 밀려 나가고 새 이미지가 좌에서 들어옴)으로, `▶▶` 는 `▶` 와 같은 방향(목록 순서대로, 기존 이미지가 좌로 밀려 나가고 새 이미지가 우에서 들어옴)으로 바뀌고, 끝에 이르면 처음(끝)으로 돌아가 반복합니다. 실행 중인 버튼은 ■ 로 바뀌고 같은 버튼을 다시 누르면 멈추며, 반대쪽 버튼을 누르면 방향이 바뀝니다. 간격은 실행 중에도 바꿀 수 있고, ◀/▶ 로 직접 넘기면 간격을 처음부터 다시 셉니다. 삭제 확인이나 파일 선택 대화상자가 떠 있는 동안은 잠시 멈추고, 이미지가 2개 미만이 되면 자동으로 멈춥니다. 받은 파일이 이미지가 아니면(exe, bat, pdf, mp3 등) 같은 창에 이미지 대신 **파일 이름 / 날짜 / 시각 / 크기** 를 큰 글자로 보여 주며, 이전/다음/삭제/up_down 탐색기/목록 추가 버튼은 이미지와 똑같이 동작합니다 (회전은 이 화면 자체를 돌림). 이 창은 텔레그램 수신과 별개로 메뉴 **F8) IP cam / 폰 연결 > 텔레그램/클라이언트 송수신 뷰어** 에서도 열 수 있습니다. 메뉴로 열 때는 이미 떠 있는 창(텔레그램 수신용 창 포함)은 그대로 두고 **새 창이 빈 목록으로 시작**하며, `목록 추가` 로 파일을 넣습니다 (이 창은 목록이 비어도 닫히지 않음). 목록의 파일은 모두 **전체 경로(full path)** 로 보관하므로 `목록 추가` 를 여러 번 눌러 **여러 폴더의 파일을 한 목록에 섞어서** 볼 수 있고, `up_down 탐색기` 는 현재 파일이 들어 있는 폴더를 열어 그 파일을 선택해 보여 주며 (목록이 비어 있을 때는 업로드 폴더), 창 제목에도 전체 경로가 표시됩니다. 텔레그램 토큰이 없어도 동작합니다. 창은 **좌우로 분할**되어 있습니다: 왼쪽(약 150픽셀) 영역은 현재 목록에 있는 파일들의 **미리보기 목록**(축소 그림 + `번호. 파일이름`, 이미지가 아닌 파일은 `파일` 표시)이고, 현재 항목은 파란색으로 강조됩니다. 목록 위/아래의 `▲` / `▼` 버튼 또는 마우스 휠로 상하 스크롤하며(더 올라/내려갈 곳이 없으면 버튼이 비활성), 항목을 클릭하면 그 파일이 오른쪽에 표시됩니다. 현재 항목이 바뀌면 자동으로 보이는 위치로 스크롤됩니다. 오른쪽 큰 영역은 기존 뷰어 동작(이미지 표시, 전환 효과, 회전 등) 그대로입니다. 미리보기 그림은 화면에 보일 때 한 번 읽어 만들어 두며 (회전하면 다시 만듦), 목록이 아주 길어도 보이는 항목만 읽습니다. GDI+ 로 직접 그리며 EXIF 회전은 반영, 움직이는 GIF 는 첫 장면만, webp/heic 등 표시할 수 없는 형식은 이미지 대신 파일 정보 화면으로 보여 줌. 프로그램을 종료하면 창도 함께 닫힘
- 받은 파일이 .mp4 또는 .mp3 이면 저장 직후 PC 의 기본 플레이어로 실행 (`UPLOAD_PLAY_MEDIA=FALSE` 로 끌 수 있음. 예전 이름 `UPLOAD_PLAY_VIDEO` 도 같은 뜻). 여러 개를 받으면 각각 실행. 그 밖의 파일(exe, bat 등)은 저장만 함. 음성 메시지(.ogg)는 실행 안 함

### PREVIOUS_SESSION_CLEAR=TRUE

시작 직후(ini 를 읽은 뒤, 캡처/명령 수신 전)에 이전 세션의 흔적을 지웁니다. 기본 FALSE.

- 삭제 대상: `log\Telegram.Log` 와 `image` 폴더 안의 모든 파일 (이 프로그램이 만든 이미지가 아니어도 삭제. 하위 폴더는 건드리지 않음). `Telegram.Log.old` 는 삭제하지 않음
- 삭제는 복구할 수 없음. TRUE 이면 재시작할 때마다 이미지가 전부 사라지므로 보관이 필요하면 FALSE 로 둘 것
- 삭제 뒤 `Telegram.Log` 에 "프로그램 시작 (이전 세션 정리 후)" 와 삭제 결과(Telegram.Log 삭제 여부, 지운 이미지 수, 실패 수)를 기록. `Telegram.Log` 가 다른 프로그램에 열려 있어 지울 수 없으면 내용만 비움
- 시작 때 한 번만 수행. `/ini` 로 추가해도 다음 시작부터 적용

### `[Telegram]` 설정 키

줄 맨 앞 `;` 또는 `#` 은 주석, 값 뒤 "공백 + `;` 또는 `#`" 도 주석입니다. 기본값은 괄호 안입니다.

| 키 | 설명 (기본값) |
|---|---|
| `TELEGRAM_BOT_TOKEN` | BotFather 의 봇 토큰. 공유/업로드 금지 |
| `TELEGRAM_CHAT_ID` | 수신 chat id. 음수(그룹)이면 `TELEGRAM_ALLOWED_USER_IDS` 필수 |
| `TELEGRAM_ALLOWED_USER_IDS` | 명령 허용 사용자 ID 목록 (`111,222`). 개인 chat 이면 생략 |

### 실행 로그 (`Telegram.Log`)

Telegram 모듈은 exe 폴더의 `log\Telegram.Log` 에 직접 기록합니다 (`log` 폴더가 없으면 자동으로 만듭니다) (콘솔 없는 `-mwindows` 빌드에서도 남음). 형식 `[날짜 시각.밀리초] [T스레드번호] 메시지`. 시작 시 버전/PID/폴더, 종료 시 종료 코드를 기록합니다. 5MB 를 넘으면 `Telegram.Log.old` 로 넘기고 새로 시작합니다. 로그에는 봇 토큰과 `/ini` 로 넣은 값은 남기지 않습니다.

처리되지 않은 예외/크래시는 앱 전체(시계, WiFiScan 포함)에 대해 원인 코드와 주소를 `Telegram.Log` 에 남기고 종료합니다.

## 카메라 영상 / IP cam / 폰 연결

메뉴 **F8) IP cam / 폰 연결 > 카메라 영상** 으로 영상 창을 엽니다. 누를 때마다 새 창이 열리므로(중복 실행 가능) 웹캠과 IP 카메라를 각각 다른 창에서 동시에 재생할 수 있습니다. 각 창은 카메라 선택, 실행/종료, 사진/동영상/연속 사진, 상태줄이 서로 독립입니다. 창을 열어도 영상은 바로 재생하지 않으며, 카메라를 고르고 **실행** 을 눌러야 재생합니다. 영상 창은 창마다 전용 스레드(자체 메시지 루프)에서 동작하므로 카메라가 느리거나 연결이 지연되어도 시계 창은 멈추지 않습니다.

- **카메라 선택 (라디오 버튼)**: `WebCam1` = Windows 가 찾은 첫 번째 웹캠(장치 #0), `WebCam2` = 두 번째 웹캠(장치 #1), `IP Cam` = 폰 카메라 앱(기본 선택). 장치 이름은 `ipcam.log` 에 남습니다.
- **실행**: 선택한 카메라 영상을 재생합니다. 이미 재생 중이면 멈추고 선택한 카메라로 다시 시작합니다 (카메라 전환). 녹화 중이었다면 먼저 저장합니다.
- **종료**: 영상 재생만 멈추고 화면을 지웁니다 (창은 열려 있으므로 다른 카메라를 골라 다시 실행 가능). 창 자체는 `Esc` 또는 X 로 닫으며 앱은 계속 실행됩니다.
- 같은 웹캠(예: WebCam1)을 두 창에서 동시에 실행할 수는 없습니다 (뒤에 실행한 창은 열기에 실패해 2초마다 재시도). 창이 여러 개일 때 같은 초에 저장하는 파일은 `_1`, `_2` ... 를 붙여 덮어쓰지 않습니다.
- 웹캠이 없거나(예: 카메라가 1개뿐인데 WebCam2 선택) 다른 곳에서 쓰는 중이면 화면에 사유를 표시하고 2초마다 자동으로 다시 시도합니다. IP Cam 은 등록된 주소가 없으면 안내 문구만 표시합니다 (웹캠은 IP cam 등록 없이 사용 가능).
- Windows 웹캠은 한 번에 한 곳에서만 열 수 있는 경우가 많으므로, **웹캠 영상을 재생하는 동안에는 텔레그램 카메라 캡처/침입 탐지(`/detectOn`)가 같은 카메라를 열지 못할 수 있고, 침입 탐지 중에는 WebCam 영상이 열리지 않을 수 있습니다.** 이 경우 한쪽을 먼저 끄세요.

폰의 카메라 앱(**DroidCam** 포트 4747, **IP Webcam** 포트 8080)이 내보내는 MJPEG 영상(`GET /video`)을 보여 줍니다. 폰과 PC 가 같은 Wi-Fi 에 있어야 하고, 폰 앱의 서버를 먼저 시작하세요.

- **IP cam 등록**: 대화상자에 IP address 와 port 번호를 입력하면 `gsHomeManager.ini` 의 `[IPCam]` (`Host`, `Port`) 에 저장됩니다. IP address 칸에 `192.168.0.70:4747` 처럼 써도 됩니다. 카메라 영상 창이 열려 있는 중에 등록하면 다음 `실행` 부터 새 주소를 씁니다.
- **카메라 영상**: 영상 창을 엽니다. 창 크기에 맞춰 비율을 유지해 표시하고, 제목줄에 카메라 이름과 fps 를 표시합니다 (멈춘 상태는 `Camera  -  stopped`). IP Cam / 웹캠 모두 연결이 끊기면 2초 간격으로 자동 재접속합니다. 잘못된 IP 로 연결을 시도하는 중에도 `종료` 가 바로 동작합니다.
  등록 대화상자 아래쪽에 DroidCam 설치 안내와 Google Play 주소가 있으며, 주소를 누르면 시스템 기본 브라우저로 열립니다.

  영상 창 맨 아래 상태줄: 저장/녹화/연속 사진/오류 안내를 `HH:MM:SS  내용` 형식으로 표시합니다 (영상 위에 겹쳐 그리지 않으며, 다음 안내가 올 때까지 유지).

  영상 창 맨 위 줄: 라디오 버튼 `WebCam1` `WebCam2` `IP Cam` + 버튼 `실행` `종료`.

  영상 창 둘째 줄 버튼 (재생 중일 때만 `사진 저장` / `동영상 촬영` 사용 가능):
  - **우로 90도 회전 / 좌로 90도 회전**: 표시를 시계/반시계 방향으로 90도씩 회전합니다 (저장되는 사진·동영상에도 적용).
  - **사진 저장**: 현재 프레임을 JPEG 로 저장합니다.
  - **동영상 촬영**: 처음 누르면 녹화 시작, 다시 누르면 녹화 종료 및 저장 (AVI / MJPG, 외부 라이브러리 없음). 녹화 중에는 제목줄에 `REC mm:ss` 가 표시되고 회전 버튼은 잠깁니다. 파일 크기가 약 1.9GB 에 이르면 자동 종료됩니다. 웹캠 영상은 녹화하는 동안만 JPEG 로 인코딩해 담습니다.
  - **저장 폴더 열기**: 저장 폴더(`IPCam\`)를 탐색기로 엽니다.
  - 저장 위치: exe 와 같은 폴더의 `IPCam\` (`ipcam_YYYYMMDD_HHMMSS.jpg / .avi`). 결과는 영상 창 맨 아래 상태줄에 표시되고 `ipcam.log` 에도 기록됩니다.

  영상 창 셋째 줄 (연속 사진, 재생 중일 때만 개시 가능):
  - **연속 사진 간격 목록(드롭다운)**: 1 / 2 / 3 / 5(기본) / 10 / 15 / 30 / 60 / 120 / 180 / 300 / 600 / 900 / 1800 / 3600 초. 연속 사진이 진행 중에는 바꿀 수 없습니다.
  - **연속 사진 개시**: 누르면 첫 장을 바로 저장하고 이후 목록의 간격마다 `사진 저장` 과 같은 방식(회전 반영, `IPCam\`)으로 저장합니다. `연속 사진 종료` 를 누를 때까지 반복합니다.
  - **연속 사진 종료**: 연속 사진을 멈춥니다 (영상 재생은 계속). 카메라 `종료` / `실행`(카메라 전환) 을 눌러도 함께 멈춥니다.
  - **연속 10회**: 개시와 같지만 10장을 저장하면 자동으로 멈춥니다. 아직 영상이 안 들어와 저장하지 못한 시도는 장수에 넣지 않습니다.
- **폰 탐색기**: 폰의 FTP 서버(CX파일 탐색기 등)에 탐색기로 접속합니다. 대화상자에 IP address / port / 사용자 이름 / 비밀번호를 입력하고 `실행` 을 누르면 `explorer.exe ftp://사용자 이름:비밀번호@IP:port` 를 실행합니다. 먼저 스마트폰에서 `CX파일 탐색기` 를 실행하고 [네트워크] → [네트워크 액세스] → [시작] 을 누르세요 (대화상자 상단 안내, Google Play 검색 링크 포함). IP address / port / 사용자 이름만 `[PhoneFtp]` 에 저장하며 **비밀번호는 저장하지도 로그에 남기지도 않습니다**.
- 로그: exe 폴더의 `log\ipcam.log` (첫 영상 창을 열 때 새로 작성하고, 창이 여러 개면 같은 파일에 이어서 기록하며 마지막 창이 닫힐 때 닫음. 웹캠 장치 이름/해상도 포함).
- 제한: 소리/HTTP 인증은 지원하지 않으며, IP Cam 영상 경로는 `/video` 로 고정입니다. 웹캠은 장치 순서(WebCam1/2)로만 고르며 해상도/프레임 속도는 카메라 기본값입니다.

## 다른 PC 원격 제어

예전 `rdp_server.exe` / `rdp_client.exe` (rdp_mini)를 이 앱에 합친 기능입니다. 서버 PC(조작당하는 PC)의 모든 모니터 화면을 JPEG 로 받아 모니터마다 창 하나씩 보여 주고, 클라이언트 창 위의 마우스 이동/클릭/휠을 서버 PC 에 전달합니다 (키보드 입력은 전달하지 않음). 프로토콜은 예전과 같아서 옛 exe 와도 서로 연결됩니다. **암호화(TLS)가 없으므로 신뢰하는 내부망에서만 사용하세요.**

두 PC 에서 모두 이 앱을 실행하고, 조작당할 PC 에서는 **다른 PC(서버)**, 조작할 PC 에서는 **다른 PC(클라이언트)** 를 엽니다. 예전 `rdp_server.ini` / `rdp_client.ini` 가 exe 폴더에 있고 `gsHomeManager.ini` 에 해당 섹션이 아직 없으면 처음 한 번 값을 가져옵니다 (원본 파일은 그대로 둠). 이후 옛 파일은 필요 없습니다.

### F8) 다른 PC(서버)

- 대화상자 위쪽에 **내 IP 주소**(이 PC 의 IPv4 전부)와 **현재 상태**(중지됨 / 대기 중 / 연결 요청 확인 중 / 연결됨 + 보낸 화면 수)가 0.5초마다 갱신되어 표시됩니다. 클라이언트에 입력할 IP 주소는 여기서 확인하세요.
- 입력 칸: `port 번호`, `비밀번호`(보이기 체크로 확인), `허용 IP`(`any` = 제한 없음, 아니면 그 IP 에서 오는 접속만 허용), `연결 요청 확인`(처음 한 번만 / 묻지 않고 자동 수락 / 접속할 때마다), `프로그램을 시작할 때 서버를 자동으로 시작`, `연결되면 화상 키보드(OSK) 실행`(클라이언트 연결이 수락된 직후 `C:\Windows\System32\osk.exe` 를 실행).
- `[저장]` 은 실행 중인 서버에도 바로 반영됩니다(비밀번호, 허용 IP, 연결 요청 확인, 화상 키보드 - 다음 접속부터). `port 번호` 변경만 `[시작](재시작)` 이 필요합니다. 화상 키보드 실행 결과는 `gsHomeManager.log` 에 남습니다.
- 버튼: **저장**(ini 에 저장하고 닫음), **시작**(저장 후 서버 시작. 이미 실행 중이면 **재시작**), **서버 종료**(서버를 멈춤), **닫기**(저장 안 함). 서버는 전용 스레드로 동작하므로 대화상자를 닫아도 계속 동작하고, 프로그램을 종료하면 함께 중지됩니다.
- 클라이언트가 접속해 비밀번호가 맞으면 서버 PC 에 `원격 연결 요청: IP` Yes/No 창이 맨 위에 뜹니다. Yes 이면 연결을 수락하고 화면 전송을 시작합니다. `처음 한 번만`(기본)이면 같은 클라이언트 IP 는 서버를 다시 시작할 때까지 다시 묻지 않습니다.
- 비밀번호가 틀리면 1초 뒤에 거부합니다 (대입 공격 지연). 접속만 하고 인증 메시지를 보내지 않는 상대는 5초 뒤에 끊습니다. 한 번에 클라이언트 한 명만 연결됩니다.
- 비밀번호는 `gsHomeManager.ini` 에 평문으로 저장됩니다 (로그에는 남기지 않음). ini 를 공유/업로드하지 마세요. 비밀번호 앞뒤 공백과 양끝 따옴표는 ini 에서 사라지므로 사용할 수 없고, 최대 60자입니다.
- **연결 로그 창**: `[시작]`(재시작) 을 누르거나, 클라이언트 연결이 수락되는 순간(프로그램 시작 때 서버를 자동으로 시작한 경우 포함) `원격 서버 연결 로그` 텍스트 창이 자동으로 열려(이미 열려 있으면 맨 앞으로), 서버-클라이언트 연결 상황(시작/중지, 접속 시도, 허용 IP 거부, 비밀번호 오류, 허용/거부, 연결/종료, 파일 수신)을 `log\gsHomeManager.log` 와 같은 내용으로 보여 줍니다. 창을 닫았다 다시 열어도 마지막 500줄은 다시 보입니다. 창 맨 위에 `파일보내기 (서버 → 클라이언트)` 버튼이 있습니다 (아래 참고). 이 창의 닫기(X) 버튼을 누르면, 클라이언트가 연결되어 있을 때 **"이 창을 닫으면 클라이언트와의 연결이 끊어집니다. 닫으시겠습니까?(Yes/No)"** 확인창이 먼저 뜹니다. `Yes` 이면 클라이언트 연결을 끊고(서버는 다음 접속을 계속 기다림) 창을 닫고, `No` 이면 창을 그대로 둡니다. 연결된 클라이언트가 없으면 확인 없이 바로 닫힙니다.
- **파일보내기 (서버 → 클라이언트)**: 연결 로그 창 맨 위의 버튼입니다. 누르면 파일 선택 대화상자(여러 개 선택 가능)가 열리고, 고른 뒤 전송 직전에 **"선택한 파일들을 클라이언트로 보내겠습니까?(Yes/No)"** 확인창이 뜨고, `Yes` 이면 연결된 클라이언트로 차례대로 전송합니다 (별도 스레드로 전송하므로 화면 전송은 멈추지 않음, 진행/결과는 이 로그 창에 표시). 연결된 클라이언트가 없으면 안내창만 뜹니다. 클라이언트 쪽에서는 파일을 받는 즉시 **텔레그램/클라이언트 송수신 뷰어** 가 자동으로 열려 받은 파일을 보여 줍니다.
- **파일 수신**: 클라이언트가 보낸 파일은 exe 폴더의 `up_down\날짜(YYYY-MM-DD)\` 폴더에 저장됩니다 (같은 이름이 있으면 `이름_1.확장자` 로 저장하고 덮어쓰지 않음, 경로/금지 문자/예약어는 정리). 파일을 받기 시작할 때마다 화면 중앙에 `클라이언트로부터 파일 수신중입니다` 팝업(1초)이 뜹니다. 받기를 마치면 텔레그램으로 받은 파일과 같은 **텔레그램/클라이언트 송수신 뷰어** 창의 목록에 들어가고(이미지는 화면에, 그 밖의 파일은 이름/날짜/시각/크기 화면), 이전/다음/삭제/실행/텔레그램으로 보내기 등을 똑같이 쓸 수 있습니다. 연결이 끊겨 끝나지 않은 파일은 지웁니다.
- port 가 이미 사용 중이면 시작할 때 경고창에 사유가 표시됩니다. Windows 방화벽이 막으면 해당 port 의 들어오는 연결을 허용해야 합니다.

### F8) 다른 PC(클라이언트)

- 입력 칸: `서버 IP address`, `port 번호`, `비밀번호`. **저장**은 ini 에 저장하고 닫으며, **연결**은 저장한 뒤 서버에 연결을 요청합니다.
- **연결**을 누르면 대화상자 안에 진행 막대와 남은 시간이 표시됩니다 (서버 접속 10초 → 서버 사용자의 승인 대기 60초). 이 동안 입력/연결/저장은 막히고 **닫기**가 **취소**로 바뀌며, 누르면 연결을 취소하고 대화상자를 닫습니다. 서버가 없거나 응답이 없거나 비밀번호가 틀리거나 서버 사용자가 No 를 누르면 사유를 오류 창으로 알려 주고 대화상자는 그대로 열려 있어 다시 시도할 수 있습니다. 연결에 성공하면 대화상자가 닫히고 원격 제어 창이 열립니다.
- 연결되면 서버 모니터마다 창 하나가 열립니다 (`원격 제어 - 모니터 N (WxH)`). 창 크기를 바꾸면 화면이 늘어나거나 줄어들고, 마우스 좌표는 창 크기에 비례해 전달됩니다. **창 하나를 닫거나 서버가 연결을 끊으면 모든 원격 제어 창이 닫힙니다.** 원격 제어는 한 번에 하나만 연결할 수 있습니다.
- **파일 전송**: 각 원격 제어 창의 타이틀 바 바로 밑에 `파일 전송` 버튼이 있습니다. 누르면 파일 선택 대화상자가 열리고, 여러 파일을 골라 [열기] 를 누르면 서버 PC 로 차례대로 전송합니다. 전송은 별도 스레드에서 하므로 원격 제어 창은 멈추지 않으며, 전송 중에는 버튼 글자가 `전송 중 2/5 (35%)` 로 바뀌고 버튼이 잠깁니다. 서버가 파일 저장을 확인하면 파일마다 성공으로 치고, 모두 끝나면 성공 개수와 실패한 파일(사유 포함)을 알림창으로 보여 줍니다. 파일 1개당 크기 제한은 없고(64KB 조각으로 전송), 전송 중에 창을 닫으면 전송을 멈춥니다. 서버와 클라이언트 양쪽 모두 이 버전 이상이어야 합니다 (옛 rdp_server.exe 로는 파일 전송이 안 되고 연결이 끊어짐).
- **파일 수신 (서버 → 클라이언트)**: 서버의 `파일보내기 (서버 → 클라이언트)` 버튼으로 보낸 파일은 클라이언트 PC 의 exe 폴더 `up_down\날짜(YYYY-MM-DD)\` 폴더에 저장됩니다 (같은 이름이 있으면 `이름_1.확장자`). 파일을 받기 시작할 때마다 화면 중앙에 `서버로부터 파일 수신중입니다` 팝업(1초)이 뜨고, 받기를 마치면 **텔레그램/클라이언트 송수신 뷰어** 가 자동으로 열려(이미 열려 있으면 목록에 추가) 그 파일을 보여 줍니다. 서버에는 저장 결과(성공/실패)를 응답합니다.
- 화면은 버튼 줄 아래에 표시되며, 버튼 줄 위에서는 서버 마우스가 움직이지 않습니다.
- 클라이언트 창은 앱의 다른 기능과 독립된 스레드에서 동작하므로 시계/WiFiScan/텔레그램에 영향을 주지 않습니다.

## 로그

- 모든 로그 파일은 exe 폴더 아래의 `log\` 폴더에 생깁니다 (없으면 자동으로 만듦).
- `gsHomeManager.log`: `log\` 폴더에 UTF-8 로그를 남깁니다. 한 줄에 한 동작이며 `[YYYY-MM-DD HH:MM:SS.mmm] 내용` 형식입니다.
  - 기록 대상: 원격 제어(서버 시작/중지, 연결 요청과 허용/거부, 클라이언트 연결 시도/종료. 비밀번호 제외), 앱 시작/종료와 설정 로드, 중복 실행 차단, 모든 메뉴 명령, 시계 모양 변경, 아나로그 전체화면/크기 변경, 알람 시각 도달/파일 실행/플레이어 자동 닫기, 프로그램 실행, 시스템 재시작 확인창과 결과, 종료 확인창과 결과, 메모 표시, 창 그룹 이동, 시계 보이기/숨기기와 트레이, 도시 창 추가/닫힘, 글꼴/바탕색 변경, 폰 탐색기 실행(비밀번호 제외), Windows 종료/로그오프 요청, 텔레그램 `/stop` `/restart` 에 의한 종료/재시작
  - 기록할 때만 파일을 열고 바로 닫으므로 상주 메모리/핸들이 없습니다.
  - 1MB 를 넘으면 `log\gsHomeManager.log.old` 로 넘기고 새로 시작합니다.
- `Telegram.Log` (`Telegram.Log.old`): Telegram 모듈의 로그 (위 Telegram 참고)
- `WiFiScan_watch.log`: WiFiScan 감시 로그. `/HomeBack`, `/NotHome` 판정마다 `[사유]` 줄 포함 (위 WiFiScan > 판정 사유 기록 참고)
- `ipcam.log`: 카메라 영상 창 로그 (IP Cam / 웹캠)
- 각 로그 파일은 메뉴 **F9) Help > 로그 보기** 의 하위 메뉴(`gsHomeManager.log` / `Telegram.Log` / `WiFiScan_watch.log` / `ipcam.log`)로 Notepad.exe 에서 열 수 있습니다. 파일이 아직 없으면 안내창이 뜹니다.

## 참고

- 모든 가상 데스크탑 적용은 비공개 셸 COM 인터페이스(`IVirtualDesktopPinnedApps`)를 사용하므로 Windows 버전에 따라 동작하지 않을 수 있습니다.
- 도시별 시간대는 레지스트리의 시간대 정보를 사용합니다.
- 아나로그 모양에서 마우스 휠이 동작하지 않으면 시계 창을 한 번 클릭해 포커스를 준 뒤 시도하세요 (Windows 의 '마우스로 가리킨 비활성 창 스크롤' 설정에 따라 다릅니다).
- 같은 봇 토큰을 쓰는 다른 프로그램(옛 `screen_telegram.exe` 등)과 동시에 실행하지 마세요 (getUpdates 409 충돌).
