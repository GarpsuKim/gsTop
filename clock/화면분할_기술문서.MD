# 화면분할 기술 문서

작성일: 2026-11-26
대상: 영원한 시계 (`com.example.clock`)

---

## 1. 개요

시계 앱의 **[화면분할]** 버튼 또는 **두 손가락 스와이프**로 화면을 둘로 나눈다.

- 시계(배경 포함)는 고른 절반에만 그린다.
- 나머지 절반에는 **폰에 설치된 앱 목록**을 보여 준다.
- 앱 목록에서 앱을 누르면 그 앱을 **"옆에 열기"(`FLAG_ACTIVITY_LAUNCH_ADJACENT`)** 로 실행한다.
  → 삼성 폰에서는 시스템 화면 분할로 시계와 그 앱이 나란히 열린다.

즉, **처음에는 앱 안에서 직접 나누고(자체 분할), 앱을 고르는 순간 안드로이드 시스템 분할로 넘어가는** 2단계 구조다.

```
[전체 화면 시계]
      │  [화면분할] 버튼 / 두 손가락 스와이프
      ▼
[자체 분할]  시계 절반 │ 앱 목록 절반        ← 이 앱이 직접 그림 (창은 여전히 화면 전체)
      │  앱 목록에서 앱 하나 누름 (LAUNCH_ADJACENT)
      ▼
[시스템 분할]  시계 앱 창 │ 고른 앱 창        ← 안드로이드(삼성 One UI)가 창을 둘로 나눔
               (자체 분할은 자동으로 꺼지고 시계가 자기 창 전체에)
```

## 2. 사용 방법

### 2.1 자리 고르기

| 화면 방향 | 버튼 메뉴 | 두 손가락 스와이프 | 시계 자리 | 앱 목록 자리 |
|---|---|---|---|---|
| 가로 | [左 분할] | ← | 왼쪽 | 오른쪽 |
| 가로 | [右 분할] | → | 오른쪽 | 왼쪽 |
| 세로 | [上 분할] | ↑ | 위 | 아래 |
| 세로 | [下 분할] | ↓ | 아래 | 위 |

- [화면분할] 버튼은 좌상단 설정 줄, [⧉ 축소] 바로 옆에 있다.
- 한 손가락 스와이프는 예전처럼 디지털 글자 스크롤 방향을 바꾼다 (두 손가락만 분할).
- 두 손가락 스와이프는 **분할되지 않은 상태에서만** 동작한다. 분할 중에는 무시한다.

### 2.2 분할된 상태에서 버튼을 누르면

- 메뉴에 **[분할 해제]만** 나온다.
- 자체 분할 → 바로 전체 화면으로 돌아온다.
- 시스템 분할 → 일반 앱은 시스템 분할을 직접 풀 수 없으므로
  "가운데 구분선을 화면 끝까지 끌면 분할이 해제됩니다" 안내만 띄운다.

### 2.3 그 밖의 동작

- 자체 분할 중 화면을 돌리면 자리를 맞춘다: 左 ↔ 上, 右 ↔ 下.
- 축소 화면(PIP)에서는 분할하지 않고 시계만 보인다.
- 분할 상태(고른 자리)는 설정에 저장한다. 앱을 껐다 켜도 분할된 채로 시작한다. [초기화] 하면 분할이 풀린다.

## 3. 왜 이 방식인가 (시행착오)

### 3.1 안드로이드의 제약

- 일반 앱이 **자기 자신을 시스템 화면 분할에 넣는 공개 API는 없다.**
- 분할했을 때 **어느 쪽(좌/우, 상/하)에 들어갈지 고르는 API도 없다.**
- 다른 앱의 화면을 **내 앱 안에 끼워 넣는 것도 불가능**하다 (보안상 막혀 있음).
- `android:resizeableActivity="true"` 는 사용자가 직접 분할할 때 이 앱도 분할에 *들어갈 수 있게 허용*할 뿐, 분할을 *실행*하지는 않는다.

### 3.2 1차 시도: 접근성 서비스 (실패 → 삭제)

| 단계 | 방법 | 결과 |
|---|---|---|
| ① | `performGlobalAction(GLOBAL_ACTION_TOGGLE_SPLIT_SCREEN)` | 삼성 폰에서 `false` 반환 → "이 기기에서는 화면 분할을 실행할 수 없습니다" |
| ② | 최근 앱 화면을 열고 → 시계 아이콘 → "분할 화면으로 열기"를 접근성으로 대신 누름 | 재부팅 직후(최근 앱에 시계만 있을 때)는 성공. 다른 앱이 쌓여 있으면 메뉴가 안 떠서 실패 (2단계) |
| ③ | 누르는 방식을 클릭 → 탭 → 길게 누르기로 바꿔 가며 재시도 + 진단 파일 | 너무 복잡해서 사용자 결정으로 **전부 취소** |

문제점:
- 사용자가 설정 → 접근성에서 서비스를 직접 켜야 함.
- 삼성 최근 앱 화면 구조(항목 이름, 위치)에 의존 → 기기·One UI 버전마다 깨질 수 있음.
- 右/下 자리 바꾸기(구분선 두 번 누르기)도 기기마다 다름.

### 3.3 최종: 자체 분할 + 옆에 열기 (성공)

- 화면을 나누는 일은 **앱이 직접 그리는 것**이므로 권한·기기 의존이 없다.
- 실제 시스템 분할은 **앱 목록에서 앱을 열 때 `FLAG_ACTIVITY_LAUNCH_ADJACENT`** 로 요청한다.
  이 플래그는 공개 API이고, 삼성 폰은 전체 화면 상태에서도 이 요청을 받아 시스템 분할로 열어 준다.
- 접근성 권한, 설정 안내, 최근 앱 화면 자동 조작이 모두 필요 없다.

## 4. 구조

### 4.1 관련 파일

| 파일 | 역할 |
|---|---|
| `app/src/main/java/com/example/clock/split/SplitScreen.kt` | `SplitSide` (좌/우/상/하), 회전 시 자리 변환, 화면 방향별 선택지 |
| `app/src/main/java/com/example/clock/MainActivity.kt` | 분할 상태 보관, 시계 영역·앱 목록 영역 배치, 배경화면 표시, 시스템 분할 감지 |
| `app/src/main/java/com/example/clock/ui/ClockScreen.kt` | [화면분할] 버튼(`SplitButton`), 두 손가락 스와이프 |
| `app/src/main/java/com/example/clock/ui/AppListPanel.kt` | 빈 절반의 앱 목록, 앱 실행(LAUNCH_ADJACENT) |
| `app/src/main/AndroidManifest.xml` | `<queries>` (설치된 앱 목록 보기) |
| `app/src/main/res/values/strings.xml` | `split*`, `app_open_failed`, `split_system_exit_hint` |

### 4.2 상태 흐름

```
MainActivity
 ├─ settings.splitSide: SplitSide?  (설정에 저장, null = 분할 안 함)   ← 사용자가 고른 자리
 ├─ landscape                       (LocalConfiguration.orientation)
 ├─ inPip                           (onPictureInPictureModeChanged)
 ├─ inMultiWindow                   (onMultiWindowModeChanged / onResume)   ← 시스템 분할 중인지
 │
 └─ activeSplit = if (inPip || inMultiWindow) null
                  else settings.splitSide?.forOrientation(landscape)        ← 실제로 그릴 자리
         │
         ├─ 시계 영역  = activeSplit 쪽 절반 (null 이면 전체)
         ├─ 앱 목록    = 반대쪽 절반 (activeSplit 이 null 이면 없음)
         └─ ClockScreen(split = activeSplit,
                        onSplitChange = { settings = settings.copy(splitSide = it); 저장 },
                        inSystemSplit = inMultiWindow)
```

- `settings.splitSide` 는 **사용자가 고른 값**, `activeSplit` 은 **지금 화면에 적용할 값**이다.
  PIP 이거나 시스템 분할 중이면 `splitSide` 값이 있어도 `activeSplit` 은 `null` → 시계가 창 전체에 그려진다.
- 화면을 돌려도 `splitSide` 는 그대로 두고 `forOrientation()` 으로 변환만 한다.
  그래서 가로 → 세로 → 가로로 돌리면 원래 자리로 돌아온다.
- 저장: `SharedPreferences` (`clock_prefs`) 의 `split_side` = `SplitSide` 순서 번호(ordinal), `-1` = 분할 안 함.
  `SplitSide` 항목 순서를 바꾸면 저장된 값의 뜻이 바뀌므로 새 항목은 끝에 추가한다.
- [초기화] 는 설정 전체를 기본값으로 되돌리므로 분할도 풀린다.

## 5. 상세 구현

### 5.1 `SplitSide` (`split/SplitScreen.kt`)

```kotlin
enum class SplitSide(@StringRes val label: Int) {
    Left, Right, Top, Bottom;

    // 화면 방향에 맞는 자리로: 가로 ↔ 세로 (左 ↔ 上, 右 ↔ 下)
    fun forOrientation(landscape: Boolean): SplitSide

    companion object {
        // 가로 → [Left, Right], 세로 → [Top, Bottom]
        fun sides(landscape: Boolean): List<SplitSide>
    }
}
```

### 5.2 영역 배치 (`MainActivity.kt`)

바깥 `Box` 는 화면 전체, 그 안에 두 영역을 `align` 으로 배치한다.

| activeSplit | 시계 영역 | 앱 목록 영역 |
|---|---|---|
| `Left` | 폭 50%, `CenterStart` | 폭 50%, `CenterEnd` |
| `Right` | 폭 50%, `CenterEnd` | 폭 50%, `CenterStart` |
| `Top` | 높이 50%, `TopCenter` | 높이 50%, `BottomCenter` |
| `Bottom` | 높이 50%, `BottomCenter` | 높이 50%, `TopCenter` |
| `null` | 전체 | 없음 |

- 시계 영역에는 기존 배경(유튜브 > 동영상 > 이미지 > 검정)과 `ClockScreen` 이 그대로 들어간다.
  시계 글자·시계판 크기는 이미 "주어진 영역에 맞춰" 계산되므로 절반 영역에서도 자동으로 줄어든다.
- `clipToBounds()` 로 배경 사진·애니메이션이 앱 목록 쪽으로 넘치지 않게 자른다.
- 앱 목록에는 `windowInsetsPadding(WindowInsets.safeDrawing)` 을 줘서 상태바·내비게이션바·카메라 구멍과 겹치지 않게 한다.

### 5.3 배경화면 보이기

```kotlin
val showWallpaper = transparency > 0f || activeSplit != null
LaunchedEffect(showWallpaper) { setWallpaperVisible(showWallpaper) }
```

- 자체 분할 중에는 창에 `FLAG_SHOW_WALLPAPER` 를 켜고 창 바탕을 투명하게 한다.
- 앱 목록 영역은 반투명 검정(`0x55000000`)만 깔려 있어서 폰 배경화면이 비쳐 보인다.
- 창 형식은 `onCreate` 에서 `PixelFormat.TRANSLUCENT` 로 고정해 두었다 (기존 투명도 기능과 공유).

### 5.4 시스템 분할 감지

```kotlin
private var inMultiWindow by mutableStateOf(false)

override fun onResume() {
    super.onResume()
    inMultiWindow = isInMultiWindowMode && !isInPictureInPictureMode
}

override fun onMultiWindowModeChanged(isInMultiWindowMode: Boolean, newConfig: Configuration) {
    super.onMultiWindowModeChanged(isInMultiWindowMode, newConfig)
    inMultiWindow = isInMultiWindowMode && !isInPictureInPictureMode
}
```

- PIP 도 안드로이드에서는 멀티 윈도우로 취급되므로 PIP 는 빼고 판단한다.
- 시스템 분할에 들어가면 자체 분할을 끄므로 "시계 창 안에서 또 반으로 나뉘는" 일이 없다.
- `manifest` 의 `configChanges` 에 `screenSize|smallestScreenSize|screenLayout|orientation` 이 있어서,
  분할·회전 때 화면이 다시 만들어지지 않고 상태가 유지된다.

### 5.5 앱 목록 (`ui/AppListPanel.kt`)

**목록 읽기**

```kotlin
val intent = Intent(Intent.ACTION_MAIN).addCategory(Intent.CATEGORY_LAUNCHER)
pm.queryIntentActivities(intent, 0)
    .filter { it.activityInfo.packageName != context.packageName }   // 시계 앱 자신 제외
    .map { 이름, ComponentName, 아이콘(48dp 비트맵) }
    .sortedBy { 이름 }
```

- 홈 화면 앱 서랍과 같은 목록이다.
- 아이콘 변환은 `produceState` + `Dispatchers.IO` 로 백그라운드에서 한다 (화면 멈춤 방지).
  읽는 동안에는 가운데에 로딩 표시를 보여 준다.
- 분할할 때마다 새로 읽으므로 그 사이 설치·삭제한 앱이 반영된다.
- 화면: `LazyVerticalGrid(GridCells.Adaptive(76.dp))` → 영역 폭에 맞춰 칸 수가 자동으로 정해지고, 많으면 스크롤된다.

**검색창**

- 목록 위의 `OutlinedTextField`. 입력할 때마다 목록을 거른다 (`matchesSearch`).
- 이름 안에 검색어가 이어서 들어 있으면 맞음. 대소문자·띄어쓰기는 무시.
- **초성 검색**: 검색어의 자음(ㄱ~ㅎ)은 이름 글자의 초성과 비교한다. `ㅋㅋㅇ` → 카카오톡, 글자와 섞어도 됨 (`카ㅋ오`).
  초성 = `(글자 - '가') / 588` 번째 자음.
- [✕] 로 검색어 지우기, 키보드의 [검색] 은 키보드만 닫음. 맞는 앱이 없으면 "찾는 앱이 없습니다".
- 키보드가 뜨면 `WindowInsets.safeDrawing`(IME 포함) 여백으로 앱 목록 영역이 키보드 위로 줄어든다.
  Android 10 이하에서도 키보드 높이가 전달되도록 `MainActivity` 에 `windowSoftInputMode="adjustResize"`.

**Android 11+ 앱 목록 제한 (`AndroidManifest.xml`)**

```xml
<queries>
    <intent>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent>
</queries>
```

- Android 11부터는 다른 앱 목록이 기본으로 가려진다. 이 선언이 있어야 런처 앱들이 보인다.
- 사용자 동의 창이 뜨는 권한이 아니며, `QUERY_ALL_PACKAGES` 같은 넓은 권한도 쓰지 않는다.

**앱 실행**

```kotlin
Intent(Intent.ACTION_MAIN)
    .addCategory(Intent.CATEGORY_LAUNCHER)
    .setComponent(component)
    .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT)
```

- `FLAG_ACTIVITY_LAUNCH_ADJACENT`: "지금 앱 옆에 열어 달라"는 요청. 시스템이 받아 주면 시스템 화면 분할로 열린다.
- 지원하지 않는 기기에서는 이 플래그가 무시되고 그 앱이 전체 화면으로 열린다 (오류 없음).
- `ActivityNotFoundException`, `SecurityException` 은 잡아서 "앱을 열 수 없습니다" 안내.

### 5.6 [화면분할] 버튼 (`ui/ClockScreen.kt` → `SplitButton`)

```kotlin
SplitButton(current = split, systemSplit = inSystemSplit, onChange = onSplitChange)
```

| 상태 | 메뉴 항목 | 누르면 |
|---|---|---|
| 분할 안 됨, 가로 | [左 분할] [右 분할] | `onChange(Left / Right)` |
| 분할 안 됨, 세로 | [上 분할] [下 분할] | `onChange(Top / Bottom)` |
| 자체 분할 중 | [분할 해제] | `onChange(null)` |
| 시스템 분할 중 | [분할 해제] | `onChange(null)` + 구분선을 끌라는 안내 |

- 아이콘: 가로 = `VerticalSplit`, 세로 = `HorizontalSplit`.
- 화면 방향은 `LocalConfiguration.orientation` (앱 창 기준). 자체 분할 중에도 창은 화면 전체이므로 기기 방향과 같다.
- PIP 중에는 버튼을 숨긴다.

### 5.7 두 손가락 스와이프 (`ui/ClockScreen.kt`)

시계 화면 최상위 `Box` 의 `pointerInput` 에서 `PointerEventPass.Initial` 로 먼저 받는다.

```
손가락 2개 이상 닿음
  └─ 모든 손가락을 뗄 때까지:
       - 움직이는 손가락들의 평균 이동량을 dx, dy 에 더함
       - 모든 이벤트를 consume() → 아래(디지털 글자 끌기, 화면 탭)로 전달 안 됨
판정 (최소 80dp):
  가로 화면: |dx| > |dy| 이고  dx ≥ 80dp → Right,  dx ≤ -80dp → Left
  세로 화면: |dy| > |dx| 이고  dy ≤ -80dp → Top,   dy ≥ 80dp → Bottom
```

- 한 손가락 동작(디지털 스크롤 방향 바꾸기, 꾹 눌러 스크롤 끄기, 탭으로 버튼 보이기)과 겹치지 않는다.
- 단, 첫 손가락이 먼저 움직이기 시작한 뒤 두 번째 손가락이 닿으면 글자가 조금 끌려갔다가 취소될 수 있다.
- **분할 중(자체 분할 또는 시스템 분할)에는 스와이프로 분할하지 않는다.** 두 손가락 동작은 그대로 받아서 버리므로
  글자 끌기 같은 다른 동작도 일어나지 않는다. 분할을 바꾸려면 [화면분할] → [분할 해제] 후 다시 고른다.
- 최신 콜백·화면 방향은 `rememberUpdatedState` 로 읽어서, `pointerInput` 을 다시 만들지 않아도 항상 현재 값이 쓰인다.

## 6. 제약 및 알려진 한계

| 항목 | 내용 |
|---|---|
| 시스템 분할 해제 | 일반 앱은 시스템 분할을 직접 풀 수 없음 → 구분선을 끌라고 안내만 함 |
| 시스템 분할 자리 | 앱 목록에서 연 앱이 시스템 분할의 어느 쪽에 들어갈지는 시스템(One UI)이 정함 |
| 다른 기기 | `LAUNCH_ADJACENT` 를 무시하는 기기에서는 고른 앱이 전체 화면으로 열림 |
| 자체 분할의 빈 절반 | 앱 목록 외의 다른 앱 화면이나 홈 화면 아이콘은 누를 수 없음 (앱 창이 화면 전체를 덮고 있음) |
| 버튼 줄 | 세로 화면 上/下 분할에서는 영역이 낮아서 설정 버튼이 여러 줄로 나뉠 수 있음 |
