## 1. 개요

시계 앱의 **[화면] 메뉴** 또는 **한 손가락 스와이프**로 화면을 둘로 나눈다.

- 한쪽에는 **시계**(배경 포함), 다른 쪽에는 **폰에 설치된 앱 목록**(삼성 홈 화면 폴더 포함)을 보여 준다.
- 두 영역 사이의 **구분선**을 끌어 비율을 바꾼다 (25% ~ 75%).
- 앱 목록에서 앱을 누르면 **"옆에 열기"(`FLAG_ACTIVITY_LAUNCH_ADJACENT`)** 로 실행한다.
  → 삼성 폰에서는 **시스템 화면 분할**로 시계와 그 앱이 나란히 열린다.

**앱 안에서 직접 나누는 단계(자체 분할)**와, 앱을 고른 뒤 **안드로이드가 창을 나누는 단계(시스템 분할)**의 2단계 구조다.

```
[전체 화면 시계]
      │  [화면] → 上/下(左/右) 분할 / 한 손가락 스와이프
      ▼
[자체 분할]   시계 │┃│ 앱 목록           ← 이 앱이 직접 그림 (앱 창은 여전히 화면 전체)
                   └ 구분선: 끌어서 비율 조절, 두 번 누르면 반반
      │  앱 목록에서 앱 하나 누름 (LAUNCH_ADJACENT)
      ▼
[시스템 분할]  시계 앱 창 │ 고른 앱 창   ← 안드로이드(삼성 One UI)가 창을 둘로 나눔
               (자체 분할은 자동으로 꺼지고, 시계가 자기 창 전체에 그려짐)
```

## 2. 사용 방법

### 2.1 분할하기

| 화면 방향 | [화면] 메뉴 | 한 손가락 스와이프 | 시계 자리 | 앱 목록 자리 |
|---|---|---|---|---|
| 가로 | [左 분할] | ← | 왼쪽 | 오른쪽 |
| 가로 | [右 분할] | → | 오른쪽 | 왼쪽 |
| 세로 | [上 분할] | ↑ | 위 | 아래 |
| 세로 | [下 분할] | ↓ | 아래 | 위 |

- **스와이프한 쪽에 시계**가 간다.
- [화면] 버튼은 좌상단 설정 줄에 있다. 한 단계 목록: **축소 / 上 분할 / 下 분할** (가로 화면은 左 / 右, 분할 중이면 축소 / 분할 해제).
- 분할 안 된 상태에서 나머지 방향(가로 ↑↓, 세로 ←→)으로 밀면 **앱 종료**.
- 두 손가락 스와이프와 디지털 글자 끌기(스크롤 방향 바꾸기)는 없앴다 (스크롤은 [스크롤 ▾] 메뉴로).
- 스와이프 전체 규칙과 구현은 5.8 참고.

### 2.2 비율 조절

- 시계와 앱 목록 사이의 **구분선(가는 선 + 가운데 손잡이)을 끌면** 시계 쪽이 화면의 25% ~ 75% 사이로 바뀐다.
- 구분선을 **두 번 누르면** 반반(50%)으로 돌아간다.
- 손을 떼면 비율이 저장된다.

### 2.3 앱 목록

| 동작 | 결과 |
|---|---|
| 앱 누르기 | 그 앱을 시계 옆에 엶 (기기가 지원하면 시스템 분할, 아니면 전체 화면) |
| 앱 길게 누르기 | 맨 위 **[고정]** 구역에 고정 / 이미 고정된 앱이면 해제 |
| 검색창에 입력 | 이름 일부 또는 **초성**으로 거름 (`ㅋㅋㅇ` → 카카오톡) |
| 검색창 [✕] | 검색어 지우기 |
| 폴더 누르기 | 그 폴더의 앱만 보임 (홈 화면 폴더 안 순서). 맨 위 [← 폴더 이름] 고정 |
| [← 폴더 이름] / [뒤로] | 폴더 닫기 → 보던 스크롤 위치로 |

- 목록 순서: **[고정]** (고정한 순서, 아이콘에 📌) → **[홈 화면 폴더]** (홈 화면 순서) → **[모든 앱]** (나머지, 이름순).
- 아직 고정한 앱이 없으면 "앱을 길게 누르면 위에 고정됩니다" 안내가 나온다.
- 검색어를 입력하면 폴더 구역은 숨기고(열린 폴더도 닫고) 전체 앱에서 거른다.
- 폴더 안의 앱도 길게 눌러 고정/해제할 수 있다.

### 2.4 분할 해제

- **한 손가락 스와이프**: 앱 목록 쪽으로 밀면 분할 해제, 시계 쪽으로 밀면 앱 종료 (5.8).
- 분할된 상태에서 [화면]을 누르면 분할 항목 대신 **[분할 해제]**가 나온다.
- **자체 분할**: 바로 전체 화면으로 돌아온다.
- **시스템 분할**: 일반 앱은 시스템 분할을 직접 풀 수 없으므로
  "가운데 구분선을 화면 끝까지 끌면 분할이 해제됩니다" 안내만 띄운다.

### 2.5 그 밖의 동작

- 화면을 돌리면 자리를 맞춘다: 左 ↔ 上, 右 ↔ 下. 시계 비율은 그대로.
- 축소 화면(PIP)에서는 분할하지 않고 시계만 보인다.
- 분할 자리·비율·고정한 앱은 저장되어 **앱을 다시 열어도 그대로** 시작한다.
- [초기화] 하면 분할이 풀리고 비율은 50% 로 돌아간다. 고정한 앱은 [초기화] 와 상관없이 유지된다.

## 3. 왜 이 방식인가 (시행착오)

### 3.1 안드로이드의 제약

- 일반 앱이 **자기 자신을 시스템 화면 분할에 넣는 공개 API는 없다.**
- 분할했을 때 **어느 쪽(좌/우, 상/하)에 들어갈지 고르는 API도 없다.**
- **다른 앱의 화면을 내 앱 안에 끼워 넣는 것은 불가능**하다 (보안상 막혀 있음).
- `android:resizeableActivity="true"` 는 사용자가 직접 분할할 때 이 앱이 분할에 *들어갈 수 있게 허용*할 뿐, 분할을 *실행*하지는 않는다.

### 3.2 1차 시도: 접근성 서비스 (실패 → 삭제)

| 단계 | 방법 | 결과 |
|---|---|---|
| ① | `performGlobalAction(GLOBAL_ACTION_TOGGLE_SPLIT_SCREEN)` | 삼성 폰에서 `false` 반환 |
| ② | 최근 앱 화면을 열고 → 시계 아이콘 → "분할 화면으로 열기"를 접근성으로 대신 누름 | 재부팅 직후(최근 앱에 시계만 있을 때)는 성공. 다른 앱이 쌓여 있으면 메뉴가 안 떠서 실패 |
| ③ | 누르는 방식을 클릭 → 탭 → 길게 누르기로 바꿔 가며 재시도 + 진단 파일 | 너무 복잡해서 **전부 취소** |

문제점:
- 사용자가 설정 → 접근성에서 서비스를 직접 켜야 한다.
- 삼성 최근 앱 화면 구조(항목 이름, 위치)에 의존 → 기기·One UI 버전마다 깨질 수 있다.
- 右/下 자리 바꾸기(구분선 두 번 누르기)도 기기마다 다르다.

### 3.3 최종: 자체 분할 + 옆에 열기 (성공)

- 화면을 나누는 일은 **앱이 직접 그리므로** 권한·기기 의존이 없다.
- 실제 시스템 분할은 **앱 목록에서 앱을 열 때 `FLAG_ACTIVITY_LAUNCH_ADJACENT`** 로 요청한다.
  공개 API이고, 삼성 폰은 전체 화면 상태에서도 이 요청을 받아 시스템 분할로 열어 준다.
- 접근성 권한, 설정 안내, 최근 앱 화면 자동 조작이 모두 필요 없다.

### 4.1 관련 파일

| `app/src/main/java/com/example/clock/ui/SplitDivider.kt` | 구분선 (끌어서 비율 조절, 두 번 누르면 반반) |
| `app/src/main/java/com/example/clock/ui/AppListPanel.kt` | 앱 목록, 검색창, 위에 고정, 홈 화면 폴더 칸·폴더 열기, 앱 실행 (LAUNCH_ADJACENT) |
| `app/src/main/java/com/example/clock/ui/HomeFolders.kt` | 삼성 홈(One UI Home) 화면 폴더 읽기 (`call()` → JSON) |
| `app/src/main/java/com/example/clock/ui/ClockScreen.kt` | [화면] 버튼 (`ScreenMenu`: 축소 / 분할 / 분할 해제), 한 손가락 스와이프 (`swipeAction`), 설정 저장·불러오기 (`splitSide`, `splitRatio`) |
| `app/src/main/AndroidManifest.xml` | `<queries>` (설치된 앱 목록 보기 + 삼성 홈 배치 정보), 삼성 홈 `READ_SETTINGS` 권한, `windowSoftInputMode="adjustResize"` |
| `app/src/main/res/values/strings.xml` | `split*`, `app_*` 문구 |

### 4.2 상태 흐름

```
MainActivity
 ├─ settings.splitSide : SplitSide?   (저장, null = 분할 안 함)        ← 사용자가 고른 자리
 ├─ settings.splitRatio: Float        (저장, 시계 쪽 비율, 기본 0.5)
 ├─ liveRatio          : Float        (구분선을 끄는 동안의 화면용 값)
 ├─ landscape                         (LocalConfiguration.orientation)
 ├─ inPip                             (onPictureInPictureModeChanged)
 ├─ inMultiWindow                     (onMultiWindowModeChanged / onResume) ← 시스템 분할 중인지
 │
 └─ activeSplit = if (inPip || inMultiWindow) null
                  else settings.splitSide?.forOrientation(landscape)    ← 실제로 그릴 자리
         │
         ├─ 앱 목록 영역 = activeSplit 반대쪽, 크기 1 − liveRatio
         ├─ 시계 영역   = activeSplit 쪽,     크기 liveRatio (null 이면 전체)
         ├─ AppListPanel()  (앱 목록 + 홈 화면 폴더, 분할할 때마다 새로 읽음)
         ├─ ClockScreen(split = activeSplit, onSplitChange = { splitSide 저장 }, inSystemSplit = inMultiWindow)
         └─ SplitDivider(ratio = liveRatio, onRatioChange = { liveRatio = it }, onDragEnd = { splitRatio 저장 })
```

- `settings.splitSide` 는 **사용자가 고른 값**, `activeSplit` 은 **지금 화면에 적용할 값**이다.
  PIP 이거나 시스템 분할 중이면 `activeSplit` 은 `null` → 시계가 창 전체에 그려진다.
- 화면을 돌려도 `splitSide` 는 그대로 두고 `forOrientation()` 으로 변환만 한다.
  그래서 가로 → 세로 → 가로로 돌리면 원래 자리로 돌아온다.
- `liveRatio` 는 `remember(settings.splitRatio)` 로 만들어서, 저장값이 바뀌면 (두 번 누르기, [초기화]) 같이 바뀐다.

### 4.3 저장값

| 저장소 (`SharedPreferences`) | 키 | 값 | [초기화] |
|---|---|---|---|
| `clock_prefs` | `split_side` | `SplitSide` 순서 번호(ordinal), `-1` = 분할 안 함 | `-1` |
| `clock_prefs` | `split_ratio` | 시계 쪽 비율 (Float), 불러올 때 0.25 ~ 0.75 로 자름 | `0.5` |
| `app_list` | `pinned` | 고정한 앱 `ComponentName.flattenToString()` 을 줄바꿈으로 이음 (고정한 순서) | 유지 |

- `SplitSide` 항목 순서를 바꾸면 저장값의 뜻이 바뀌므로, 새 항목은 끝에 추가한다.
- 와이파이 / 텔레그램 빌드는 앱 ID 가 달라서 모든 저장값이 앱마다 따로다.

## 5. 상세 구현

### 5.1 `SplitSide` (`split/SplitScreen.kt`)

```kotlin
// 순서 = 설정 저장값(ordinal). 새 항목은 끝에 추가할 것.
enum class SplitSide(@StringRes val label: Int) {
    Left, Right, Top, Bottom;

    // 화면 방향에 맞는 자리로: 가로 ↔ 세로 (左 ↔ 上, 右 ↔ 下)
    fun forOrientation(landscape: Boolean): SplitSide

    companion object {
        const val DEFAULT_RATIO = 0.5f   // 시계 쪽 비율 기본값
        const val MIN_RATIO = 0.25f
        const val MAX_RATIO = 0.75f

        // 가로 → [Left, Right], 세로 → [Top, Bottom]
        fun sides(landscape: Boolean): List<SplitSide>
    }
}
```

### 5.2 영역 배치 (`MainActivity.kt`)

바깥 `BoxWithConstraints` 는 화면 전체, 그 안에 두 영역을 `align` 으로 배치한다. r = `liveRatio`.

| activeSplit | 시계 영역 | 앱 목록 영역 |
|---|---|---|
| `Left` | 폭 r, `CenterStart` | 폭 1−r, `CenterEnd` |
| `Right` | 폭 r, `CenterEnd` | 폭 1−r, `CenterStart` |
| `Top` | 높이 r, `TopCenter` | 높이 1−r, `BottomCenter` |
| `Bottom` | 높이 r, `BottomCenter` | 높이 1−r, `TopCenter` |
| `null` | 전체 | 없음 |

- 시계 영역에는 기존 배경(유튜브 > 동영상 > 이미지 > 검정)과 `ClockScreen` 이 그대로 들어간다.
  시계 글자·시계판 크기는 "주어진 영역에 맞춰" 계산되므로 영역이 줄면 자동으로 작아진다.
- 시계 영역은 `clipToBounds()` 로 배경 사진·애니메이션이 앱 목록 쪽으로 넘치지 않게 자른다.
- 앱 목록에는 `windowInsetsPadding(WindowInsets.safeDrawing)` 을 줘서
  상태바·내비게이션바·카메라 구멍·키보드와 겹치지 않게 한다.

### 5.3 구분선 (`ui/SplitDivider.kt`)

```kotlin
SplitDivider(
    side = activeSplit,
    ratio = liveRatio,
    totalPx = 좌우 분할이면 화면 폭, 상하 분할이면 화면 높이,
    onRatioChange = { liveRatio = it },                     // 끄는 동안
    onDragEnd = { settings.splitRatio = liveRatio; 저장 },   // 손을 뗄 때
    onReset = { 0.5 로 되돌리고 저장 },                      // 두 번 누르기
)
```

- **위치**: 시계가 왼쪽/위면 `ratio × totalPx`, 오른쪽/아래면 `(1 − ratio) × totalPx`.
  `align(TopStart)` + `offset` 으로 그 자리에 놓는다.
- **모양**: 보이는 선 2dp (흰색 30%) + 가운데 손잡이 6×48dp (흰색 80%, 둥근 모서리).
- **잡는 폭**: 16dp. 양쪽 영역에 8dp 씩만 걸쳐서, 구분선 옆의 설정 버튼·앱 아이콘을 덜 가린다.
- **끌기** (`detectDragGestures`):
  - 끌기 시작할 때의 비율을 기억하고, 이동량을 누적해서 `시작 비율 + 누적 이동량 / totalPx` 로 계산한다.
    화면 갱신보다 터치 이벤트가 빨라도 이동량을 잃지 않는다.
  - 시계가 왼쪽/위면 오른쪽/아래로 끌수록 시계가 커지고, 반대쪽이면 부호를 뒤집는다.
  - `MIN_RATIO` ~ `MAX_RATIO` (25% ~ 75%) 로 자른다.
  - 끄는 동안은 `liveRatio` 만 바꿔 바로 반영하고, 손을 떼거나 취소되면 저장한다.
- **두 번 누르기** (`detectTapGestures(onDoubleTap)`): 50% 로 되돌리고 저장.
- 콜백은 `rememberUpdatedState` 로 읽어서 `pointerInput` 을 다시 만들지 않아도 최신 값이 쓰인다.

### 5.4 배경화면 보이기

```kotlin
val showWallpaper = transparency > 0f || activeSplit != null
LaunchedEffect(showWallpaper) { setWallpaperVisible(showWallpaper) }
```

- 자체 분할 중에는 창에 `FLAG_SHOW_WALLPAPER` 를 켜고 창 바탕을 투명하게 한다.
- 앱 목록 영역은 반투명 검정(`0x55000000`)만 깔려 있어서 폰 배경화면이 비쳐 보인다.
- 창 형식은 `onCreate` 에서 `PixelFormat.TRANSLUCENT` 로 고정해 두었다 (검은 배경 투명도 기능과 공유).

### 5.5 시스템 분할 감지

```kotlin
private var inMultiWindow by mutableStateOf(false)

override fun onResume() {
    super.onResume()
    inMultiWindow = isInMultiWindowMode && !isInPictureInPictureMode
}

override fun onMultiWindowModeChanged(isInMultiWindowMode: Boolean, newConfig: Configuration) {
    super.onMultiWindowModeChanged(isInMultiWindowMode, newConfig)
    inMultiWindow = isInMultiWindowMode && !isInPictureInPictureMode
}
```

- PIP 도 안드로이드에서는 멀티 윈도우로 취급되므로 PIP 는 빼고 판단한다.
- 시스템 분할에 들어가면 자체 분할을 끄므로 "시계 창 안에서 또 나뉘는" 일이 없다.
- manifest 의 `configChanges` 에 `screenSize|smallestScreenSize|screenLayout|orientation` 이 있어서,
  분할·회전 때 화면이 다시 만들어지지 않고 상태가 유지된다.

### 5.6 앱 목록 (`ui/AppListPanel.kt`)

**목록 읽기**

```kotlin
val intent = Intent(Intent.ACTION_MAIN).addCategory(Intent.CATEGORY_LAUNCHER)
pm.queryIntentActivities(intent, 0)
    .filter { it.activityInfo.packageName != context.packageName }   // 시계 앱 자신 제외
    .map { 이름, ComponentName, 아이콘(48dp 비트맵) }
    .sortedBy { 이름 }
```

- 홈 화면 앱 서랍과 같은 목록이다.
- 아이콘 변환은 `produceState` + `Dispatchers.IO` 로 백그라운드에서 한다. 읽는 동안에는 로딩 표시.
- 분할할 때마다 새로 읽으므로 그 사이 설치·삭제한 앱이 반영된다.
- 화면: `LazyVerticalGrid(GridCells.Adaptive(76.dp))` → 영역 폭에 맞춰 칸 수가 정해지고, 많으면 스크롤된다.

**Android 11+ 앱 목록 제한 (`AndroidManifest.xml`)**

```xml
<uses-permission android:name="com.samsung.android.launcher.permission.READ_SETTINGS" />
<queries>
    <intent>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent>
    <!-- 삼성 홈 화면 배치 (폴더) 읽기 -->
    <provider android:authorities="com.sec.android.app.launcher.settings" />
</queries>
```

- Android 11부터는 다른 앱 목록이 기본으로 가려진다. `<intent>` 선언이 있어야 런처 앱들이 보이고,
  `<provider>` 선언이 있어야 삼성 홈의 배치 정보 창구에 닿을 수 있다.
- 사용자 동의 창이 뜨는 권한이 아니며, `QUERY_ALL_PACKAGES` 같은 넓은 권한도 쓰지 않는다.
- 삼성 홈 `READ_SETTINGS` 는 삼성 홈이 선언한 **일반(normal) 권한**이라 설치할 때 자동으로 받는다 (동의 창 없음).

**검색창**

- 목록 위의 `OutlinedTextField`. 입력할 때마다 거른다 (`matchesSearch`). 검색어는 화면을 돌려도 유지 (`rememberSaveable`).
- 이름 안에 검색어가 이어서 들어 있으면 맞음. 대소문자·띄어쓰기는 무시.
- **초성 검색**: 검색어의 자음(ㄱ~ㅎ)은 이름 글자의 초성과 비교한다.
  - `ㅋㅋㅇ` → 카카오톡, 글자와 섞어도 됨 (`카ㅋ오`).
  - 초성 = `ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ` 의 `(글자 − '가') / 588` 번째.
- [✕] 로 검색어 지우기, 키보드의 [검색] 은 키보드만 닫음. 맞는 앱이 없으면 "찾는 앱이 없습니다".
- 키보드가 뜨면 `safeDrawing`(IME 포함) 여백으로 앱 목록 영역이 키보드 위로 줄어든다.
  Android 10 이하에서도 키보드 높이가 전달되도록 `MainActivity` 에 `windowSoftInputMode="adjustResize"`.

**위에 고정**

- 앱을 **길게 누르면** (`combinedClickable(onLongClick)`) 고정 / 해제. 진동 + "위에 고정했습니다 / 고정을 풀었습니다".
- 목록을 두 구역으로 나눈다 (구역 제목은 `GridItemSpan(maxLineSpan)` 으로 한 줄 전체):
  - **[고정]**: 고정한 순서, 아이콘 오른쪽 위에 핀 표시.
  - **[모든 앱]**: 나머지, 이름순. 고정한 앱은 여기에 다시 나오지 않는다.
- 검색어가 있으면 두 구역 모두 거른다 (고정한 앱 중 맞는 것이 여전히 먼저).
- 저장: `app_list` / `pinned` (4.3 참고). 지운 앱은 목록에 안 나올 뿐 저장값에는 남아서, 다시 설치하면 고정된 채로 보인다.

**홈 화면 폴더 (`ui/HomeFolders.kt`)**

안드로이드에는 다른 앱이 홈 화면 배치를 읽는 공용 API 가 없다. 삼성 홈(One UI Home, 패키지 `com.sec.android.app.launcher`)이
다른 앱용으로 열어 둔 배치 정보 창구를 쓴다.

```kotlin
val uri = Uri.parse("content://com.sec.android.app.launcher.settings")
val result = contentResolver.call(uri, "get_home_only_item_info", null, Bundle())  // extras 는 null 이면 안 됨
val json = (result.get("result_list") as Array<String>).joinToString("")          // JSON 배열 하나
```

- 삼성 홈 설정의 홈 화면 방식에 따라 한쪽만 채워져 있다. 앞에서부터 폴더가 있는 첫 결과를 쓴다.
  - `get_home_item_info`: "홈 화면과 앱스 화면" 방식
  - `get_home_only_item_info`: "홈 화면만 사용" 방식 (사용자 폰은 이쪽)
- JSON 항목 (확인된 칸):

  | 칸 | 폴더 | 폴더 안 앱 |
  |---|---|---|
  | `type` | `"folder"` | `"app"` (`"shortcut"` 도 받음) |
  | `id` | 폴더 id | 항목 id |
  | `containerId` | `-100` 홈 화면, `-101` 아래 고정줄(독) | **폴더 id** |
  | `screen`, `positionX`, `positionY` | 쪽 번호, 칸 위치 | (`screen` = −1) |
  | `rank` | | 폴더 안 순서 |
  | `title` | 폴더 이름 | 앱 이름 |
  | `component` | | `"패키지/.액티비티"` |
  | `hidden` | `"UNHIDDEN"` 이 아니면 뺌 | 같음 |

- 폴더 순서: 홈 화면 쪽(`screen`) → 위에서 아래(`positionY`) → 왼쪽에서 오른쪽(`positionX`), 독 폴더는 마지막.
- 폴더 안 앱: `rank` 순서. `component` 를 `ComponentName.unflattenFromString(...).flattenToString()` 으로 바꿔
  앱 목록의 key 와 맞추고, 같은 액티비티가 없으면 같은 패키지의 앱으로 맞춘다. 목록에 없는 앱은 빠지고, 비면 폴더도 빠진다.
- 실패하면 (삼성 폰이 아님, 권한 없음, 이름·형식이 바뀜) 빈 목록 → 폴더 없이 예전 앱 목록. 결과는 logcat 태그 `ClockFolders`.
- 폴더 칸: 48dp 둥근 사각형(흰색 33%) 안에 앞쪽 앱 4개의 17dp 아이콘을 2×2 + 폴더 이름.
- 폴더를 열면 전체 목록 대신 [← 폴더 이름] 줄(목록 밖에 고정) + 폴더 전용 `LazyVerticalGrid` (`key(폴더 id)` 로 늘 맨 위부터).
  전체 목록의 `LazyGridState` 는 위로 끌어올려 두어, 폴더를 닫으면 보던 위치로 돌아온다.
  [뒤로] 는 `BackHandler(enabled = 폴더 열림)` 으로 폴더만 닫는다.

시행착오:

| 단계 | 방법 | 결과 |
|---|---|---|
| ① | launcher3 표준 `content://…settings/favorites` 조회 (`itemType`, `container` …) | 권한은 받았지만 이 버전(HoneySpace)은 **cursor = null**. `favorites_homeOnly`, `appOrder` 등도 모두 null |
| ② | 삼성 홈 APK(`/system/priv-app/TouchWizHome_2017`)를 꺼내 dex 문자열에서 `get_*_item_info` 같은 `call()` 이름을 찾음 | 후보 확보 |
| ③ | 시계 앱 안에서 후보를 모두 불러 logcat 에 기록 | `get_home_only_item_info` 가 폴더 16개를 JSON 으로 줌. `get_home_item_info` 는 extras 가 null 이면 NPE → `Bundle()` 을 넘김 |

**앱 실행**

```kotlin
Intent(Intent.ACTION_MAIN)
    .addCategory(Intent.CATEGORY_LAUNCHER)
    .setComponent(component)
    .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT)
```

- `FLAG_ACTIVITY_LAUNCH_ADJACENT`: "지금 앱 옆에 열어 달라"는 요청. 시스템이 받아 주면 시스템 화면 분할로 열린다.
- 지원하지 않는 기기에서는 이 플래그가 무시되고 그 앱이 전체 화면으로 열린다 (오류 없음).
- `ActivityNotFoundException`, `SecurityException` 은 잡아서 "앱을 열 수 없습니다" 안내.

### 5.7 [화면] 버튼 (`ui/ClockScreen.kt` → `ScreenMenu`)

한 단계 목록 (`FlatMenuButton`): 누르면 항목이 바로 나온다.

```kotlin
ScreenMenu(
    onEnterPip = { 축소 화면(PIP) 으로 },     // null 이면 "축소" 항목 없음
    current = split,
    systemSplit = inSystemSplit,
    onSplitChange = if (inPip) null else onSplitChange,   // null 이면 분할 항목 없음
)
```

| 상태 | 메뉴 항목 | 누르면 |
|---|---|---|
| 항상 | [축소] | 축소 화면(PIP) 으로 전환 |
| 분할 안 됨, 세로 | [上 분할] [下 분할] | `onSplitChange(Top / Bottom)` |
| 분할 안 됨, 가로 | [左 분할] [右 분할] | `onSplitChange(Left / Right)` |
| 자체 분할 중 | [분할 해제] | `onSplitChange(null)` |
| 시스템 분할 중 | [분할 해제] | `onSplitChange(null)` + 구분선을 끌라는 안내 |

- 버튼 아이콘·분할 항목 아이콘: 가로 = `VerticalSplit`, 세로 = `HorizontalSplit`.
- 화면 방향은 `LocalConfiguration.orientation` (앱 창 기준). 자체 분할 중에도 앱 창은 화면 전체이므로 기기 방향과 같다.
- 항목이 하나도 없으면 버튼도 그리지 않는다. PIP 중에는 버튼 묶음 전체가 숨겨진다.

### 5.8 한 손가락 스와이프 (`ui/ClockScreen.kt` → `swipeAction`)

모든 모드 공통. 규칙은 순수 함수 `swipeAction(dir, split, systemSplit, landscape)` 하나에 모여 있다.

| 상태 | ← | → | ↑ | ↓ |
|---|---|---|---|---|
| 가로, 분할 안 됨 | 左 분할 | 右 분할 | **앱 종료** | **앱 종료** |
| 세로, 분할 안 됨 | **앱 종료** | **앱 종료** | 上 분할 | 下 분할 |
| 左 시계 | **앱 종료** | 분할 해제 | – | – |
| 右 시계 | 분할 해제 | **앱 종료** | – | – |
| 上 시계 | – | – | **앱 종료** | 분할 해제 |
| 下 시계 | – | – | 분할 해제 | **앱 종료** |
| 시스템 분할 중 | 분할 안 됨 일 때의 "앱 종료" 방향만, 분할 방향은 아무 일 없음 | | | |

- 분할 중: **시계 쪽으로 = 앱 종료, 앱 목록 쪽으로 = 분할 해제**, 직각(–) = 아무 일 없음.
- 규칙은 `split` (SplitSide) 기준이라 화면 방향과 상관없이 같다.

**손가락 추적** (시계 화면 최상위 `Box` 의 `pointerInput`, **Main 단계**)

```
손가락 1개가 닿음 (Press)
  └─ 뗄 때까지:
       - 두 번째 손가락이 닿으면 → 무효
       - 이동 이벤트가 이미 소비돼 있으면 (자식이 먼저 가져감: 투명도 슬라이더, 메뉴 스크롤) → 무효
       - 이동량을 dx, dy 에 더함
       - 이동이 touchSlop 을 넘으면 그 이동을 consume()
판정 (최소 100dp, 많이 움직인 쪽 기준) → SwipeDir → swipeAction() → 진동 + 분할 / 분할 해제 / finish()
```

- **Main 단계**에서 보므로 자식(슬라이더·메뉴·구분선 아래 요소)이 먼저 받는다. 우리 쪽은 "아무도 안 가져간 끌기"만 스와이프로 본다.
- **touchSlop 을 넘으면 consume()**: 화면 탭(`combinedClickable`, 버튼 보이기/숨기기)은 Final 단계에서 소비 여부를 보고 탭을 취소하므로,
  스와이프 뒤에 버튼이 깜빡이지 않는다. 같은 이벤트에서 자식 소비 여부를 먼저 확인한 뒤 소비하므로 자기 소비를 자식 소비로 착각하지 않는다.
- 앱 종료는 [닫힘] 시간이 다 됐을 때와 같은 `activity.finish()` 다 (화면 켜짐 유지가 풀리고, 음악·동영상은 앱을 나갈 때처럼 멈춤).
- 콜백·화면 방향·분할 상태는 `rememberUpdatedState` 로 읽어서 `pointerInput` 을 다시 만들지 않는다 (키는 `inPip` 만).
- 예전 동작과의 관계: 두 손가락 스와이프(분할·종료)와 디지털 글자 끌기(스크롤 방향 바꾸기)는 삭제했다.
  화면 꾹 누르기(스크롤 끄기)는 그대로다.

## 6. 제약 및 알려진 한계

| 항목 | 내용 |
|---|---|
| 시스템 분할 해제 | 일반 앱은 시스템 분할을 직접 풀 수 없음 → 구분선을 끌라고 안내만 함 |
| 시스템 분할 자리·비율 | 앱 목록에서 연 앱이 어느 쪽에, 어떤 비율로 들어갈지는 시스템(One UI)이 정함 |
| 다른 기기 | `LAUNCH_ADJACENT` 를 무시하는 기기에서는 고른 앱이 전체 화면으로 열림 |
| 자체 분할의 앱 목록 쪽 | 앱 목록 외의 다른 앱 화면이나 홈 화면 아이콘은 누를 수 없음 (앱 창이 화면 전체를 덮고 있음) |
| 구분선 근처 터치 | 구분선 양쪽 8dp 안의 버튼·아이콘을 누르면 구분선이 잡힐 수 있음 |
| 좁은 영역 | 비율을 25% 쪽으로 줄이면 시계 쪽 설정 버튼이 여러 줄로 나뉘거나, 앱 목록 칸 수가 줄어듦 |
| 키보드 | 세로 上/下 분할에서 검색 키보드가 뜨면 앱 목록이 많이 좁아질 수 있음 |
| 두 빌드 함께 설치 | 와이파이·텔레그램 빌드는 분할 설정·고정 앱이 따로 저장됨 |
| 홈 화면 폴더 | 삼성 홈 전용. 공개 API 가 아니라 삼성 홈이 다른 앱용으로 열어 둔 `call()` 이라, One UI 업데이트로 이름·JSON 형식이 바뀌면 폴더만 사라짐 (앱 목록은 그대로) |
| 홈 화면 폴더 범위 | 홈 화면(독 포함)의 폴더만. 앱스 화면 폴더(`get_apps_item_info`)는 넣지 않음 |
| 메뉴 위 스와이프 | 메뉴가 열린 채 그 위에서 옆으로 길게 밀면 스와이프로 처리될 수 있음 (메뉴의 세로 스크롤은 무시됨) |
| 좁은 시계 쪽 | 분할 중 버튼을 띄우면 투명도 슬라이더가 버튼 줄과 겹치거나 글자가 구분선에 잘릴 수 있음 |

- 앱 목록에서 앱 선택 → 시스템 화면 분할로 시계 옆에 열림: 정상 ("처음에 의도했던 대로 완벽하게 동작")
- 이전 방식(접근성 서비스)은 `GLOBAL_ACTION_TOGGLE_SPLIT_SCREEN` 이 막혀 있고 최근 앱 화면 자동 조작이 불안정해서 삭제함
- 분할 저장, 검색, 고정, 비율 조절 구분선: 사용 중 (구분선 두 번 누르기로 50% 복귀도 adb 로 확인)
- **한 손가락 스와이프** (adb `input swipe` + 설정 파일 `split_side`·맨 앞 화면 확인): 세로 8가지, 가로 11가지 경우 모두 표대로 동작.
  짧게 누르면 버튼 보이기, 스와이프 뒤 버튼 깜빡임 없음, 투명도 슬라이더 끌기는 앱 종료로 처리되지 않음
- **홈 화면 폴더**: 폴더 16개를 홈 화면 순서대로 표시, 폴더 열기(카카오 7개·음악 6개), [← 폴더 이름] 고정, [뒤로] 로 닫고 보던 위치 복귀
- 테스트 참고: adb `input` 좌표는 실제 화면(1440×3200) 기준이다 (미러링 화면 864×1920 아님).
  삼성 플로우 스마트 뷰가 연결돼 있으면 덮개 창(`galaxycontinuity … blackscreen`)이 몇 초마다 떠서 캡처가 검고 터치를 가로챈다 → 덮개가 있으면 밀어서 치운 뒤 조작
